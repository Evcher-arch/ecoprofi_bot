Инструкция по обновлению токена индексера

Когда нужна эта инструкция

Если пришло сообщение «Индексатору нужен вход оператора» с действием «access login», нужно повторно войти в VK для индексатора. Обновление материалов приостановлено, но поиск по уже опубликованным материалам продолжает работать.

Доступ сохраняется на VPS, после чего индексатор продлевает его автоматически. Само уведомление не показывает, почему продление не удалось.

1. Подключитесь к VPS

На своём компьютере откройте PowerShell и выполните:

ssh -t root@79.174.78.44

2. Запустите вход на VPS

После подключения выполните:

cd /opt/ecoprofi
docker compose -f compose.yaml -f compose.vps.yaml --profile indexer run --rm indexer python -m ecoprofi.indexer access login

Терминал покажет ссылку для входа и будет ждать ввода адреса возврата. Оставьте команду работающей.

3. Авторизуйтесь в браузере

Откройте показанную ссылку в браузере на своём компьютере.

Войдите в аккаунт VK, у которого есть доступ к платным материалам клуба.

После входа браузер перейдёт на адрес вида:

https://localhost/callback?...

Страница не загрузится — это ожидаемо. Для этой процедуры не нужно запускать сайт на localhost.

Скопируйте полный адрес из адресной строки браузера, включая все параметры после знака вопроса. Вставьте его в ожидающий терминал VPS и нажмите Enter.

Ввод скрыт: символы при вставке не отображаются. Это нормально.

Адрес возврата содержит одноразовый код. Вставляйте его только в приглашение команды; не отправляйте в чат и не сохраняйте в этой инструкции.

4. Убедитесь, что доступ сохранён

При успешном входе появится сообщение:

Доступ сохранён. Платная лента читается: постов N.

N — количество постов, которое вернул VK.

Если вход завершился ошибкой, не переходите к обновлению: сохраните текст ошибки без ссылки возврата и секретных значений для диагностики. Для новой попытки снова выполните команду access login и откройте новую ссылку, которую она выдаст.

5. Запустите обновление сразу

Чтобы не ждать следующего планового срока, выполните на VPS из /opt/ecoprofi:

docker compose -f compose.yaml -f compose.vps.yaml --profile indexer run --rm indexer python -m ecoprofi.indexer run update

Дождитесь завершения команды.

6. Проверьте состояние

Выполните:

docker compose -f compose.yaml -f compose.vps.yaml --profile indexer run --rm indexer python -m ecoprofi.indexer status

При необходимости отдельно проверьте доступ к VK:

docker compose -f compose.yaml -f compose.vps.yaml --profile indexer run --rm indexer python -m ecoprofi.indexer access check

При успехе проверка покажет «Доступ действует. Платная лента читается: постов N.».

Перезапускать VPS или бота для обновления доступа не требуется. Работающий индексатор подхватит сохранённый доступ. Плановые обновления продолжатся, если расписание включено.

ЗАПУСК ИНДЕКСАТОРА ВНЕ РАСПИСАНИЯ

Чтобы немедленно запустить обновление материалов, подключитесь к VPS по SSH и выполните:

cd /opt/ecoprofi
docker compose -f /opt/ecoprofi/compose.yaml -f /opt/ecoprofi/compose.vps.yaml --profile indexer run --rm indexer python -m ecoprofi.indexer run update

Команда запускает обновление сразу, без ожидания планового времени. Расписание при этом не меняется. Дождитесь завершения команды.

Доступ к VK должен действовать. Если требуется вход, сначала выполните процедуру обновления доступа из разделов выше.

Если уже идёт другой проход индексатора, команда сообщит об этом. Дождитесь его завершения.

После завершения проверьте состояние:

docker compose -f compose.yaml -f compose.vps.yaml --profile indexer run --rm indexer python -m ecoprofi.indexer status

ЕСЛИ ВХОД ЗАВЕРШАЕТСЯ ОШИБКОЙ URLError (VK ID)

Эта ошибка означает сбой сетевого запроса к VK ID. Повторение входа само по себе не устраняет сетевую причину.

28.11.2026 на VPS подтверждено расхождение MTU: внешний интерфейс ens3 — 1450, сеть Docker — 1500. HTTPS к обоим адресам id.vk.ru работал с хоста, но из контейнера зависал при установлении TLS. При уменьшении TCP-сегмента соединение устанавливалось сразу.

На VPS применено согласование размера TCP-сегментов с маршрутом (TCPMSS) для трафика сети ecoprofi_internal через внешний интерфейс. Бот и контейнеры не останавливались. После исправления проверено успешное TLS-соединение к обоим адресам VK ID как из indexer-daemon, так и из отдельного контейнера indexer.

Настройку при запуске VPS и Docker применяет сервис ecoprofi-docker-mss.service. Файлы настройки в проекте:

deploy/docker-mss.sh
deploy/systemd/ecoprofi-docker-mss.service

Проверка сервиса на VPS:

systemctl status ecoprofi-docker-mss.service --no-pager

После пересоздания сети Docker или сброса правил межсетевого экрана примените настройку повторно:

systemctl restart ecoprofi-docker-mss.service

После устранения сетевой ошибки заново выполните access login по инструкции выше. Откройте новую ссылку, выданную новым запуском команды. Адрес возврата от предыдущей попытки использовать нельзя.

Исправление сети само по себе не выполняет вход в VK: дождитесь сообщения «Доступ сохранён. Платная лента читается», затем запускайте run update.
