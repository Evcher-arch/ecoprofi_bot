# Конституция проекта «Экопрофи_бот»

## Основные принципы

### I. Состав корпуса определяется расписанием

Бот помогает участнику найти материал цикла «ЭкобезБЕЗграниц». Основанием для индексации
служит строка расписания и её связь с публикацией, презентацией, записью или разбором.
Строка «в разработке» сохраняется в каталоге до появления материала. При обнаружении
материалов индексатор сохраняет идентификаторы VK, стабильную ссылку, версию и вид связи
(вложение или упоминание). Пометка «Клуб» действует на конкретный материал строки.
Неясную аудиторию уточняет редактор до публикации материала в поиске.

### II. Права проверяются до поиска и передачи текста

При запуске VK Mini App сервер проверяет подпись параметров запуска и идентификатор
приложения, затем привязывает сессию к проверенному `vk_user_id`. Перед каждым поиском,
включая уточнения и обращения к кэшу, сервер определяет доступную участнику аудиторию.
При неизвестных правах доступен только публичный корпус. До проверки механизма членства
закрытая выдача разрешена лишь согласованным тестировщикам с проверенными правами.

Права оператора дают индексатору право чтения источника. Право участника на выдачу
проверяется отдельно. Фрагменты и кэш наследуют аудиторию материала. При изменении прав
сервис закрывает прежние версии и сбрасывает затронутый кэш. Внешняя векторизация и
генерация в Yandex AI Studio разрешены для всех материалов. 

### III. Каждая рекомендация подтверждается источником

Бот выдаёт до трёх материалов с пояснением и стабильной ссылкой. Для слайда страницу
подтверждает текст этой страницы, для письма реквизиты сверяются с оригиналом, для
эпизода интервал берётся из обработанной дорожки. Карточка видео сама по себе позволяет
рекомендовать запись целиком. Временный адрес дорожки используется только для чтения.

Сервис объединяет полнотекстовые и векторные совпадения и группирует их по лекциям.
Модель получает только разрешённые выдержки как цитируемые данные и идентификаторы
кандидатов. Сборщик принимает только кандидатов текущего поиска, берёт ссылки и
координаты из каталога. При слабом совпадении бот задаёт уточняющий вопрос. Если корпус
не подтверждает ответ, бот сообщает об отсутствии подходящего материала.

### IV. Обновление сохраняет целостность опубликованного индекса

Оригиналы остаются у владельца. Индексатор обрабатывает вложения в памяти либо удаляет
временный файл по завершении обработки. Поисковый фрагмент связан с версией материала,
аудиторией и местом в источнике. Для вектора фиксируется модель эмбеддинга.
Повтор с тем же идентификатором, версией источника и версией обработчика сохраняет один
результат. Новая версия публикуется атомарно после полной обработки.

Тайм-аут, пустой ответ API, отказ доступа и ошибка разбора получают разные статусы.
После временного сбоя повторяется только затронутая операция с задержкой и ограничением
числа попыток. Предыдущая доступная версия сохраняется при сетевом сбое. Пропуск поста
на странице ленты требует проверки. Подтверждённое удаление исключает источник из поиска.

### V. Приёмка опирается на воспроизводимую проверку

Для значимой пробы фиксируются дата, среда, способ авторизации, материал, наблюдаемый
результат и открытый вопрос. Вывод ограничивается проверенной цепочкой и ролью.
Например, получение WebVTT на Windows подтверждает чтение дорожки. Переход к эпизоду
проверяют отдельно, открыв ссылку в плеере. Серверный цикл проверяют от строки расписания
до выдачи из опубликованного индекса под публичной и клубной ролями.

## Каналы и эксплуатация

Рабочий вход — плитка «Найти лекцию» в меню «Экопрофи». Она открывает отдельное
VK Mini App с личным чатом. Уточнения остаются в сессии участника. Переписка с
администрацией сохраняет собственный канал. Тестовый адаптер Bots Long Poll проверяет
сообщество и тестировщика, вызывает тот же модуль поиска и отвечает в исходный диалог.

В серверном пилоте HTTPS-шлюз направляет запросы API в FastAPI. Индексатор читает
источники в фоне. PostgreSQL с pgvector хранит каталог, права, очередь и индекс во
внутренней сети Docker Compose. Ключ сообщений, секрет Mini App и учётные данные
индексатора доступны только соответствующим серверным процессам. Коды авторизации,
токены, адреса возврата и подписанные URL исключаются из журналов. До автономного
запуска оператор проверяет продление доступа и процедуру повторного входа при отзыве.

По идентификатору операции оператор может установить версию индекса, источники ответа,
длительность и исход поиска. На пилоте измеряются p95 времени ответа, доля пустой
выдачи, возраст индекса, очередь ошибок и стоимость ответа и обновления лекции.
Пороги устанавливаются по результатам замеров. Резервную копию PostgreSQL проверяют
пробным восстановлением.

## Приёмка пилота

- **Первый локальный сценарий.** По вопросу «загрязняющих веществ» найти эпизод разбора
  2909-р, проверить читаемость выдержки после устранения повторов и открыть ссылку
  в плеере. Ориентир из пробы — 26:03–26:30. Пользователь без доступа к материалу
  не должен получить закрытую выдержку.
- **Текстовый пилот.** Редактор размечает 20 вопросов по 5–10 лекциям. Поиск успешен,
  если нужный материал входит в первую тройку, ссылка открывается под тестовой ролью,
  а фрагмент подтверждает пояснение. Предложенная в архитектуре цель — не менее
  16 успехов из 20. Обоснованные отказы вне корпуса учитываются отдельно. Время ручного
  поиска и поиска через бота сравнивают на одних заданиях.
- **Рабочий канал.** На телефоне и компьютере проверяют вход через плитку, уточнение
  и открытие источника. Отдельно проверяют изоляцию двух диалогов, отказ при подмене
  параметров запуска и отсутствие поискового запроса в сообщениях администрации.
- **Поиск по речи.** Сначала используют пригодные субтитры. Резервное распознавание
  Whisper large-v3 через faster-whisper испытывают при наличии разрешённого аудио.
  При отсутствии звука сохраняют карточку и статус ожидания источника.

## Порядок изменений

Основанием служит [архитектурное решение пилота](../../Архитектура_бота_Экопрофи.docx),
включая протокол проб (приложение Б) и критерии приёмки SDD (приложение В).
В спецификации указывают применимые критерии из приложения В. При проверке плана
в разделе Constitution Check указывают, как будут соблюдены затронутые принципы.
При приёмке задачи результат сверяют с наблюдаемым критерием.

Если новая проба меняет способ интеграции, одновременно обновляют раздел архитектуры,
затронутую схему и критерий приёмки. Поправка к конституции описывает основание,
изменённое правило и влияние на действующие спецификации. Решения о составе корпуса,
аудитории и внешней обработке подтверждает владелец. Несовместимое изменение или отмена
принципа повышает MAJOR, новый принцип или существенное расширение — MINOR, уточнение
формулировки без изменения требований — PATCH. При каждой поправке обновляются версия
и дата изменения.
