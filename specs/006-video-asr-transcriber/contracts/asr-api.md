# Контракт: API распознавателя `/asr/v1/`

**Сервер:** `https://miniapp.bot-alimony.ru/asr/v1/`. Существующий шлюз nginx проксирует префикс во внутренний сервис `asr-gateway:8100` (research R2).

**Клиент:** распознаватель на ПК владельца. Соединение всегда открывает ПК.

## Общие правила

- **Аутентификация.** Заголовок `Authorization: Bearer <ключ распознавателя>`. Неверный или отозванный ключ получает `401 {"error":{"code":"unauthorized"}}` без уточнения причины.
- **Формат.** Тела в JSON, UTF-8. Ошибки приходят в формате шлюза Mini App: `{"error":{"code","message","retryable"}}`.
- **Лимиты nginx на `/asr/`:**
  - `limit_req` 2 запроса в секунду с burst 10;
  - `client_max_body_size` 1 МБ, а для `.../result` — 16 МБ (gzip);
  - `proxy_buffering off` для `audio`;
  - `access_log off`.
- **Журналы.** Ни сервер, ни ПК не пишут в журнал ключ, `lease_id` целиком (только первые 8 символов) и временные адреса VK.
- **Повторы.** Все запросы идемпотентны по `lease_id`. При сетевом сбое клиент повторяет запрос с экспоненциальной задержкой от 5 секунд до 5 минут.

## `POST /asr/v1/session` — «я на связи»

Отправляется каждые 5 минут в простое и при запуске распознавателя.

Запрос:

```json
{"version": "asr-worker 0.1.0", "model": "large-v3", "compute_type": "float16",
 "device": {"gpu": "NVIDIA GeForce RTX 3080", "vram_total_mb": 10240, "vram_free_mb": 9100}}
```

Ответ `200`:

```json
{"run": {"id": 41, "kind": "initial", "until": null} ,
 "paused": false, "next_due_at": "2026-11-29T01:00:00+03:00"}
```

- `run: null` — окно закрыто. Тогда клиент ждёт и повторяет `session`.
- `run` не пустой — окно открыто. Сервер сам открыл запуск или вернул уже открытый. Клиент переходит к `lease`.
- Если клиент сообщил, что видеопамяти недостаточно, сервер не открывает запуск. Если запуск уже открыт, сервер закрывает его с исходом `resource_unavailable`.

## `POST /asr/v1/jobs/lease` — взять задание

Запрос: `{"run_id": 41}`.

- **`200` — задание выдано:**

```json
{"lease_id": "8d3c…", "lease_expires_at": "…", "deadline_at": "…",
 "job": {"ref": "-95098598_456239017", "duration_s": 5412, "source_version": "…"},
 "audio": {"href": "/asr/v1/jobs/8d3c…/audio", "format": "ogg/opus", "sample_rate": 16000, "channels": 1}}
```

- **`204`** — очередь пуста. Клиент вызывает `runs/{id}/finish` с `queue_empty`.
- **`409 window_closed`** — окно закрылось или стоит пауза.

## `GET /asr/v1/jobs/{lease_id}/audio` — скачать звук

- **`202`** + `Retry-After: 15` — сервер ещё готовит звук: получает свежий адрес VK и извлекает звук через `ffmpeg`.
- **`200`** или **`206`** — `audio/ogg`, поддерживается `Range` для докачки. Также отдаются `Content-Length` и `X-Audio-Sha256`.
- **`409 lease_invalid`** — аренда истекла, отменена или передана. Клиент удаляет всё по заданию и берёт следующее.
- **`410 audio_unavailable`** — сервер не смог получить звук. Задание уже в `audio_unavailable` с причиной. Клиент берёт следующее.

Временный адрес VK клиенту не передаётся ни в каком виде (R1).

## `POST /asr/v1/jobs/{lease_id}/heartbeat` — продлить аренду

Запрос: `{"processed_s": 1830}`. Отправляется каждые 2 минуты.

- **`200`** `{"lease_expires_at": "…", "continue": true}`.
- **`continue: false`** — окно закрылось или стоит пауза. Клиент прерывает работу и вызывает `release`.
- **`409 lease_invalid`** — например, появились субтитры и задание отменено. Клиент прерывает работу и удаляет файлы.

## `POST /asr/v1/jobs/{lease_id}/result` — расшифровка

`Content-Encoding: gzip`, тело:

```json
{"processor_version": "asr-1/large-v3", "language": "ru", "audio_sha256": "…",
 "audio_seconds": 5412.3, "processing_seconds": 402.8,
 "segments": [{"start_ms": 0, "end_ms": 4120, "text": "…", "avg_logprob": -0.21,
               "no_speech_prob": 0.02, "compression_ratio": 1.4}]}
```

- **`202`** `{"state": "transcribed"}` — расшифровка сохранена, публикация идёт в фоне. После этого клиент удаляет звук и расшифровку у себя.
- **`200`** `{"state": "published" | "transcribed"}` — повтор того же результата. Дублей нет.
- **`409 lease_invalid`** — результат по недействующей аренде не принимается (FR-08).
- **`422 invalid_result`** — нарушены интервалы, пустой массив или чужой `audio_sha256`. Задание получает `retry` с причиной `decode`.

## `POST /asr/v1/jobs/{lease_id}/failure` — неудача

Запрос: `{"kind": "decode" | "gpu_unavailable" | "timeout" | "internal", "detail": "краткий текст без адресов"}`. Ответ `200`.

- **`decode`, `timeout`, `internal`** → `retry`, растёт `attempts`. После 3 попыток в запуске задание откладывается до следующего запуска, растёт `failed_runs`.
- **`gpu_unavailable`** → задание возвращается в `queued` без расхода попыток, запуск закрывается с исходом `resource_unavailable`.

## `POST /asr/v1/jobs/{lease_id}/release` — вернуть без результата

Окно закрылось, распознаватель останавливают, или Windows уходит в сон. Задание возвращается в `queued` без расхода попыток. Ответ `200`.

## `POST /asr/v1/runs/{run_id}/finish` — закончить запуск

Запрос: `{"outcome": "queue_empty" | "window_closed" | "paused" | "error"}`. Ответ `200`.

Первичный проход сервер помечает завершённым (`initial_pass = done`) сам, когда у всех заданий с `initial = true` есть итоговый исход.

## Поведение распознавателя (клиент)

1. Отправить `session`. Если `run = null`, ждать 5 минут.
2. `lease` → `audio`: при `202` подождать `Retry-After`. Затем проверить `X-Audio-Sha256` и распознать, отправляя `heartbeat` каждые 2 минуты.
3. Отправить `result`, затем удалить звук и расшифровку на ПК. Повторять `lease`, пока не придёт `204` или `409 window_closed`.
4. При старте удалить всё, что осталось на томе `asr-tmp` после аварийной остановки (FR-15).
5. Если сервер недоступен, повторять с задержкой. Аренда на сервере истечёт сама, и задание вернётся в очередь.
