# План реализации 006: распознавание записей без субтитров

**Дата:** 2026-11-25. **Функция:** `006-video-asr-transcriber`. **Git-ветка:** `master`.
**Основание:** [spec.md](spec.md), конституция v1.1.0, [решение владельца о транскрибации](../005-vps-migration/spec.md#решение-владельца-о-транскрибации-2026-11-24), [research.md](research.md).
**Статус:** технический проект подготовлен. Кода и проб нет.

## Summary

Записи без пригодных субтитров распознаются Whisper large-v3 на ПК владельца с GPU. Сервер (VPS 005) остаётся единственным рабочим контуром.

- **Сервер.** На VPS появляется сервис `asr-gateway` (образ `indexer`, роль `ecoprofi_indexer`). Он ведёт очередь и аренду заданий, график распознавания (`asr_schedule`, независимый от `run_schedule`) и первичный проход. Он сам получает звук с доступом оператора, извлекает его через `ffmpeg` в Opus 16 кГц моно и публикует расшифровку теми же эпизодами и атомарными версиями, что и субтитры.
- **ПК.** Распознаватель `asr-worker` работает в Docker Desktop с GPU. Каждые 5 минут он сообщает серверу о себе по HTTPS `/asr/v1/` через существующий шлюз nginx, с ключом распознавателя. Когда окно открыто, он берёт задания, скачивает только звук и возвращает отрезки с таймкодами.
- **Графики.** По умолчанию распознавание идёт по воскресеньям с 01:00 МСК, окно 8 часов. Сразу после развёртывания выполняется первичный проход по всей начальной очереди без ограничения окном.

### Доставка звука и канал связи: итог сравнения (подробно — research R1, R2)

| | Достоинства | Ограничения | Решение |
| --- | --- | --- | --- |
| **Звук через сервер** | Подписанный адрес VK и доступ оператора не покидают VPS. Не зависит от привязки адреса к IP. На ПК идёт около 16 МБ на лекцию вместо 400–800 МБ. Статусы «звук недоступен» ставятся там, где видна причина | Трафик (скачивание видео) и 1–2 минуты одного ядра VPS на запись. Временный файл на диске VPS. Больше серверного кода и `ffmpeg` в образе | **Выбрано** |
| **Временный адрес напрямую на ПК** | Почти нулевая нагрузка на VPS. Проще сервер | Подписанный адрес клубной записи уходит на ПК. Возможный отказ из-за привязки к IP. ПК обращается к VK, вопреки ограничению 5. Истекающий адрес. Полное видео на ПК | Запасной вариант при нехватке ресурсов VPS (решение владельца) |
| **HTTPS `/asr/v1/` на шлюзе** | Не нужны новые порты (005 SC-08). Нечувствителен к блокировкам VPN-протоколов. На ПК ничего не настраивается на уровне ОС. Те же правила шлюза и журналов | Публичная точка входа держится на ключе: нужны хеш, отзыв, лимиты. Общий шлюз с Mini App | **Выбрано**, mTLS — необязательное усиление |
| **WireGuard** | API не виден из интернета. Взаимная аутентификация ключами | Новый UDP-порт нарушает 005 SC-08. Нестабилен из-за ТСПУ. Нужна настройка ОС и WSL2 на ПК. Протокол приложения всё равно нужен | Отклонено |
| **SSH-туннель** | Нет новых портов, ключи | У ПК появляется учётная запись на хосте VPS. Нужен самодельный перезапуск на Windows | Отклонено |

## Technical Context

| Область | Решение |
| --- | --- |
| **Язык** | Python 3.12, как у образов `app` и `indexer` |
| **Зависимости, сервер** | FastAPI и uvicorn (как у `bot`), psycopg 3, httpx, `ffmpeg` (apt в образе `indexer`) |
| **Зависимости, ПК** | `faster-whisper` 1.x (CTranslate2 ≥ 4.5, CUDA 12, cuDNN 9), httpx. Базовый образ `nvidia/cuda:12.4.1-cudnn-runtime-ubuntu22.04` |
| **Данные** | PostgreSQL 16 + pgvector. Миграция `migrations/005_asr.sql`: `asr_worker`, `asr_schedule`, `asr_job`, `asr_transcript`, `asr_run`, поле `material_version.speech_source`. Временные файлы — тома `asr-tmp` на VPS (лимит 2 ГБ) и на ПК |
| **Проверки** | pytest на `test-db` (`tests/asr/`), проба по [quickstart.md](quickstart.md) §2, неделя наблюдения §5 |
| **Платформа** | VPS: Ubuntu 24.04, 2 vCPU, 2 ГБ RAM + 2 ГБ swap, 20 ГБ NVMe. ПК: Windows 11, Docker Desktop (WSL2), GPU NVIDIA — модель и объём видеопамяти фиксирует проба |
| **Тип проекта** | Расширение веб-сервиса: новый внутренний сервис API, клиент-распознаватель, миграция, правка шлюза и индексатора |
| **Цели** | Первичный проход начинается не позже 15 минут после развёртывания. Плановый запуск — не позже 15 минут после назначенного времени (SC-03, SC-04). Скорость распознавания — ориентир не ниже 10 ч записи за час работы, измеряется (SC-09) |
| **Ограничения** | Одно задание за раз. `asr-gateway` ≤ 300 МБ RAM, `ffmpeg` с `nice 10`. Наружу только 22, 80, 443. Временные адреса VK и ключи — вне журналов. ПК не получает доступ оператора и не обращается к VK. Графики индексатора и распознавания независимы |
| **Масштаб** | Начальная очередь — все записи с `waiting_source` (число фиксирует T-проба, ориентир десятки–сотни записей по 1–2 ч). Один распознаватель |

Неизвестных `NEEDS CLARIFICATION` нет. Факты, которые фиксирует проба (поля медиа у `video.get`, привязка адреса к IP, видеопамять и скорость ПК), выбора не меняют. Единственное исключение — оговорённый запасной путь R1.

## Проектные решения

1. **Звук через сервер** (R1): `asr-gateway` → `video.get` (свежий адрес) → `ffmpeg -vn -ac 1 -ar 16000 -c:a libopus -b:a 24k`. Берётся минимальное качество видео или отдельная звуковая дорожка HLS/DASH. Файл на `asr-tmp` удаляется после результата, отказа или истечения аренды.
2. **HTTPS-канал** (R2): `deploy/asr-location.inc` подключается в server-блок 443. В нём `location /asr/v1/` с `limit_req`, отдельными `client_max_body_size` и `proxy_buffering off`. Ключ распознавателя хранится в БД хешем (R2a).
3. **Распознаватель в Docker Desktop с GPU** (R3): `compose.asr.yaml`, проект `ecoprofi-asr`, `Dockerfile.asr`, том моделей, `restart: unless-stopped`.
4. **График на сервере** (R4): `asr_schedule` — по умолчанию вс 01:00, окно 8 ч, без догона. `initial_pass` даёт первичный проход сразу после развёртывания.
5. **Аренда 20 минут с продлением** (R5). Результат только по действующему `lease_id`. Предел — 1,5 длительности звука + 15 мин.
6. **Публикация в `asr-gateway`** (R6): фильтр отрезков без речи и зацикленных, затем `build_episodes` из `ecoprofi/indexer/subtitles.py`, эмбеддинги и атомарная версия `speech_source = 'asr'`, `recognized = true`.
7. **Связь с индексатором** (R7): upsert заданий для записей без дорожки. Распознанная версия не затирается карточкой. Появление субтитров отменяет задание.
8. **Наблюдение** (R8): `python -m ecoprofi.asr status`, оповещения `asr_permanent:*` и `asr_silent`.

**Решение о структуре.** Серверная часть живёт в образе `indexer`: ей нужен доступ оператора и роль `ecoprofi_indexer`. Клиент `ecoprofi/asr/worker` не импортирует серверные модули, БД и доступ оператора, и собирается в отдельный образ для ПК.

## Риски

| Риск | Последствие | Мера |
| --- | --- | --- |
| `video.get` не отдаёт медиа для записей сообщества или платной ленты с доступом оператора | Звук недоступен, функция даёт только статусы | Проба первой задачей. При отказе записи получают `audio_unavailable`, вопрос выносится владельцу, скрытого обхода нет |
| VPS (2 ГБ RAM) не тянет `ffmpeg` рядом с остальными сервисами | Деградация поиска во время подготовки | Одно задание, `nice`, потоковое чтение без загрузки в память, замер в пробе. Запасной путь — вариант B решением владельца |
| Docker Desktop не видит GPU или Windows уходит в сон | Запуски не идут | Проверка `nvidia-smi` в quickstart §0. `release` при остановке, аренда истекает сама. Сводка показывает последнюю связь |
| Галлюцинации Whisper на тишине и музыке | Мусор в выдержках | VAD, фильтр `no_speech_prob` и `compression_ratio`, порог минимума речи, проверка выдержек в SC-02 |
| Второй процесс с доступом оператора | Гонка продления | Существующий `pg_advisory_lock` в `ecoprofi/indexer/access.py`. Тест на одновременное продление |
| Утечка ключа распознавателя | Чужой забирает звук клубных записей | Хеш, отзыв, лимиты, видимость аренд в `status`. mTLS как усиление |

## Complexity Tracking

Нарушений Constitution Check нет. Новый сервис `asr-gateway` оправдан требованием независимого графика и мгновенной публикации (R6). Отдельный образ распознавателя оправдан тяжёлыми зависимостями CUDA, которым не место в серверных образах.

## Вне 006

- распознавание на VPS или в облаке;
- ручная правка расшифровок;
- диаризация и перевод;
- субтитры в самом VK;
- несколько распознавателей одновременно;
- mTLS (включается позже без изменения API);
- вариант B доставки звука — только решением владельца по итогам пробы.
