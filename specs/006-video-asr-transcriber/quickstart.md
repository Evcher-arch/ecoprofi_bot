# Quickstart 006: проверка распознавания записей без субтитров

Сценарии проверки для приёмки. Результаты записываются в `acceptance.md` с полями принципа V: дата, среда, способ авторизации, материал, наблюдаемый результат, открытый вопрос. Контракты: [asr-api.md](contracts/asr-api.md), [operator-commands.md](contracts/operator-commands.md). Модель данных: [data-model.md](data-model.md).

Сокращение для VPS:

```bash
ASR="docker compose -f compose.yaml -f compose.vps.yaml --profile indexer run --rm indexer python -m ecoprofi.asr"
```

## 0. Предпосылки

- **VPS из 005 работает.** Применена миграция `005_asr.sql`, в образе `indexer` есть `ffmpeg`, сервис `asr-gateway` в состоянии Up. Шлюз проходит `nginx -t`, в него подключён `asr-location.inc`.
- **ПК владельца:**
  - Windows 11, Docker Desktop с бэкендом WSL2;
  - драйвер NVIDIA с поддержкой CUDA 12;
  - `docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi` показывает видеокарту.
- **Стенд ПК из 005 остановлен** (005 FR-07). На ПК запускается только проект `ecoprofi-asr`.
- **Внешняя поверхность VPS** по-прежнему ограничена портами 22, 80 и 443 (005 SC-08).

## 1. Регистрация распознавателя

```bash
$ASR worker add owner-pc            # ключ показывается один раз
```

На ПК ключ кладётся в `secrets/asr_worker_token` (права только у владельца). Затем:

```powershell
docker compose -f compose.asr.yaml up -d
docker compose -f compose.asr.yaml logs -f asr-worker
```

**Ожидается:** в журнале распознавателя запись «на связи». В `$ASR worker list` у `owner-pc` последняя связь не старше 5 минут, видна модель GPU. Запрос с неверным ключом получает `401`:

```bash
curl -s -o /dev/null -w '%{http_code}' -X POST https://miniapp.bot-alimony.ru/asr/v1/session -H 'Authorization: Bearer x'   # 401
```

## 2. Проба цепочки (история 1, SC-01)

Перед первичным проходом поставить распознавание на паузу (`$ASR pause`) и выбрать две записи из `$ASR jobs --state queued`: одну открытую и одну из платной ленты клуба.

```bash
$ASR probe <owner>_<item>
```

**Записать в протокол:**

- поля медиа `video.get`: `files`, `hls`, `dash`;
- есть ли отдельная звуковая дорожка;
- время подготовки звука и его размер;
- пик ЦП и RAM на VPS (`docker stats`).

Затем `$ASR run-now` и `$ASR resume` — распознаватель берёт задания. По каждой из двух записей:

- длительность звука и время распознавания (`$ASR status`);
- три отрезка, сверенные с оригиналом в плеере: расхождение не больше ±5 секунд;
- после завершения на ПК пуст том `asr-tmp`, на VPS пуст том `asr-tmp`:

```powershell
docker compose -f compose.asr.yaml exec asr-worker ls -A /tmp/asr
```

- запись, звук которой недоступен, получила `audio_unavailable` с причиной.

## 3. Первичный проход (FR-19, SC-03)

Сразу после развёртывания (и после пробы — `$ASR resume`):

- `$ASR status` показывает «Первичный проход: идёт», время начала не позже чем через 15 минут после развёртывания;
- выключить ПК посреди записи, через 30 минут включить. Задание вернулось в очередь (`worker_lost` у запуска), проход продолжился, частичной версии в поиске нет (SC-06);
- по окончании: «Первичный проход: завершён», у каждой записи начальной очереди есть исход. Итог по исходам записать в протокол;
- `$ASR schedule show` — следующий запуск в воскресенье 01:00 МСК.

## 4. Поиск по распознанной записи (история 2, SC-02)

Под ролью подписчика в Mini App задать три вопроса по содержанию контрольной распознанной записи.

**Ожидается:**

- запись в первой тройке с выдержкой и подписью «речь распознана автоматически»;
- ссылка открывает плеер на эпизоде, звучащий фрагмент подтверждает выдержку;
- под ролью неподписчика и при сбое проверки подписки выдачи нет.

## 5. Независимость графиков (история 3, SC-04, SC-08)

- `$ASR schedule set --days 7 --at 01:00 --window 8h` не меняет время в `python -m ecoprofi.indexer schedule show`, и наоборот;
- неделя наблюдения: индексатор запускается в 07:00 и 19:00, не больше двух опросов в сутки. Распознаватель запускается только в воскресенье с 01:00, не позже 01:15 при включённом ПК;
- неделя с выключенным ПК: оповещений о сбое распознавания нет, Mini App и поиск по остальным материалам работают. Оповещение `asr_silent` появляется только после 14 суток.

## 6. Повторы и субтитры (история 4, SC-05, SC-06)

- `$ASR run-now` дважды подряд: число версий и эпизодов распознанных записей не меняется;
- запись, у которой появились субтитры (или контрольная запись, для которой субтитры добавлены владельцем). После ближайшего прохода индексатора у неё `speech_source = subtitles`, задание `cancelled / subtitles`, в поиске один комплект эпизодов.

## 7. Журналы и секреты (SC-07)

```bash
docker compose logs asr-gateway indexer-daemon | grep -E -i 'okcdn|vkuser|vkvd|sig=|Bearer|access_token' | wc -l   # 0
```

```powershell
docker compose -f compose.asr.yaml logs asr-worker | Select-String -Pattern 'okcdn','vkvd','sig=','Bearer'   # пусто
```

## 8. Автотесты

```bash
docker compose --profile test run --rm tests pytest tests/asr
```

Покрывают:

- переходы `asr_job`;
- аренду и отклонение результата по недействующей аренде;
- открытие окна (график, первичный проход, догон, пауза);
- сборку эпизодов из отрезков с фильтром «галлюцинаций»;
- отказ индексатора затирать распознанную версию карточкой.
