# Задачи: автономный индексатор

**Основание**: документы из `specs/003-autonomous-indexer/` — [спецификация](spec.md), [план](plan.md), [основания решений](research.md) (R1–R22), [модель данных](data-model.md), [контракт оператора](contracts/operator-commands.md), [контракт оповещений](contracts/alerts.md), [порядок проверки](quickstart.md); принципы — [конституция v1.0.0](../../.specify/memory/constitution.md).

**Решения владельца от 2026-11-22**:
- автоматический опрос расписания лекций и лент — не чаще двух раз в сутки, утром и вечером (по умолчанию 07:00 и 19:00 по Москве);
- поиск доступен только подписчикам клуба Экопрофи (VK Donut). Подписку проверяет bot ключом сообщества при каждом обращении (`ecoprofi/bot/club.py`); список тестировщиков и роли `public`/`unknown` для участников отменены. Это изменение bot ведётся отдельно и в задачи 003 не входит;
- исключение из проверки подписки — владелец и администратор сообщества (VK ID 177068782), у которой формально нет подписки. Список — `CLUB_EXEMPT_IDS` в `.env` у `bot`; исключённый участник допускается без запроса к VK, в том числе при сбое проверки, и не закрывает причину `club`.

**Что новая политика меняет для индексатора** (spec.md, «Допущения»; research.md, R21–R22):
1. Доступ оператора к платной ленте зависит от его собственной подписки или прав в сообществе и не равен допуску участника. Если доступ пропадёт, лента вернёт меньше записей или ничего. Без проверки индексатор посчитает платные публикации пропавшими, а найденные в открытой ленте — открытыми. Поэтому платная лента проверяется перед каждой порцией (FR-23; задачи T005, T019, T026).
2. Сбой проверки подписки в bot закрывает поиск всем. Оператор узнаёт об этом из оповещения `club` (FR-24; задачи T024, T027).
3. Вычисление аудитории материала (`public`/`club`/неясная) не меняется. Подписчику открыты оба вида, поэтому на выдачу влияет только неясная аудитория: «ждёт решения редактора» и оповещение `editor` сохраняются (FR-22).
4. Живые проверки через бота выполняются из учётной записи подписчика; учётная запись без подписки получает отказ про клуб (задачи T023, T040).

**Ждут подтверждения владельца**: стенд на ПК разработчика; оповещения личным сообщением тестового сообщества одному оператору; поправка к принципу II конституции (T004).

**Тесты**: включены. План требует проверок на настоящей PostgreSQL с подменами VK, VK ID и AI Studio; время и паузы подставляются. Проверки bot используют подмену подписки `FakeClub` из `tests/integration/conftest.py`.

**Организация**: задачи сгруппированы по историям спецификации. История 2 (доступ) идёт раньше истории 1 (полный проход), потому что проход дольше часа невозможен без продления. Обе истории — P1.

## Формат: `[ID] [P?] [История] Описание`

- **[P]** — можно вести параллельно: другие файлы, нет зависимости от незавершённых задач.
- **[US1]–[US5]** — история из spec.md.
- **👤 Владелец** — нужны учётная запись, действие в VK или решение владельца. Исполнитель останавливается, даёт точную инструкцию и ждёт результата. Секреты владелец вводит сам в `.env` или в скрытое приглашение.
- Пути отсчитываются от корня проекта. `ix` означает `docker compose run --rm indexer python -m ecoprofi.indexer`. Наблюдения живых проверок записываются в `specs/003-autonomous-indexer/acceptance.md` с датой, средой, способом авторизации и результатом; значения доступа, коды и адреса файлов туда не вносятся.
