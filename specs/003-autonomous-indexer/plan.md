# План реализации автономного индексатора

**Функция** 003-autonomous-indexer · [Спецификация](spec.md) · 2026-11-22

## Результат и границы

Стенд 002 на ПК разработчика получает постоянно работающий индексатор. Оператор один раз входит через VK ID командой индексатора; индексатор хранит доступ на отдельном томе, сам продлевает его и обходит все строки расписания с материалами порциями с продолжением после остановки. Сервис `indexer-daemon` запускает обновление в назначенное время. О событиях, требующих действия, оператор получает личное сообщение от тестового сообщества. Приёмка охватывает OPS-01 в части продления доступа и повтора после отказа, NET-01, а также VK-01 и DOC-01 на полном расписании.

Вне плана: сервер клуба и вход через зарегистрированный адрес возврата, мини-приложение, оценка качества поиска на полном корпусе, распознавание речи, интерфейс редактора.

## Технический контекст

| Параметр | Значение |
| --- | --- |
| Язык и среда | Python 3.12 в контейнере, Docker Compose на Windows |
| Основа из 001–002 | FastAPI, psycopg 3, pgvector, httpx; PostgreSQL 16 с pgvector; Yandex AI Studio; Tesseract в образе индексатора |
| Новые зависимости | `tzdata` (московское время в контейнере). Планировщик, хранилище доступа и оповещения — на стандартной библиотеке |
| Хранилище | Тот же том PostgreSQL, миграция `003_autonomy.sql` без изменения каталога; новый том `indexer-secrets` для значений доступа |
| Тесты | pytest; VK, VK ID и AI Studio заменены подменами; время и паузы подставляются; интеграционные — на БД в памяти |
| Вид проекта | Сервисы bot, vk-adapter, новый сервис indexer-daemon; разовые команды оператора в образе индексатора |
| Объём | 68 строк расписания с материалами, 269 связей с публикациями; платная лента — 1039 постов, открытая — 8939; порция — 5 лекций |
| Производительность | Порогов нет: длительность полного прохода и планового обновления, число обращений к VK и к внешней обработке измеряются при приёмке |
| Ограничения | Рабочий токен живёт час, токен обновления заменяется при каждом продлении; значения доступа — только на томе индексатора, не в БД, журнале, отчётах и оповещениях; ключ сообщений остаётся только у vk-adapter; подписанные адреса файлов не сохраняются; одновременно один проход |

Неизвестные вынесены в пробы R6 и R10 в [основаниях решений](research.md); они не блокируют проектирование. Нерешённых вопросов нет.

## Границы компонентов

| Компонент | Что меняется | Доступ |
| --- | --- | --- |
| db | Проходы и их лекции, расписание запусков, состояние доступа (без значений), оповещения; расширение задания индексации | Роли прежние; bot получает чтение новых таблиц и отметку отправки оповещений |
| indexer (команды) | Вход и хранилище доступа с продлением; проход порциями с продолжением; плановое обновление по разнице вложений; постоянный сбой; ограничение частоты; создание оповещений; сводка | Том `indexer-secrets`, номер приложения VK ID, эмбеддинги документов, запись в каталог |
| indexer-daemon (новый) | Цикл: расписание запусков → проход. Тот же код, что у команд | Как у indexer |
| bot | Очередь оповещений для адаптера, отметка отправки, проверка устаревания индекса; причина `club` при сбое проверки подписки | Чтение проходов и состояния доступа; ключ сообщества Экопрофи для проверки подписки (изменение 2026-11-22); без тома секретов |
| vk-adapter | Опрос очереди оповещений между циклами Long Poll и отправка оператору | Ключ сообщений, служебный ключ, идентификатор оператора |

## Порядок реализации

1. **Схема.** Миграция 003 по [модели данных](data-model.md); права ролей; проверка на копии рабочей БД: счётчики каталога и контрольный ответ не меняются.
2. **Доступ.** Хранилище значений на томе с атомарной заменой (R2, R3); вход `access login` (R1); продление под блокировкой и по сроку (R4); разделение причин `auth` и `denied` (R5); состояние доступа и отметки проверки (R18); команды `access check`, `access forget`. Клиент VK получает токен из хранилища при каждом вызове вместо значения, переданного при создании. Пробы R6 и R10 при первом живом входе.
3. **Проход порциями.** Проход и список лекций, блокировка одного прохода (R8, R9); поиск вложений для порции (R10); пропуск материалов, обработанных в этом проходе; остановка по `auth`, лимиту VK и лимиту внешней обработки с сохранением места (R13, R14); счётчик и состояние постоянного сбоя, `requeue` (R12); счётчик пропуска публикации в ленте; команды `run full`, `run cancel`, `status`; отчёт редактору дополняется (R20). Выборка пилота перестаёт ограничивать обход (R19).
4. **Оповещения.** Таблица и правила одной открытой причины (R17); создание и закрытие причин в индексаторе; очередь и отметка отправки в bot с проверкой устаревания (R15, R16); опрос и отправка в vk-adapter по [контракту](contracts/alerts.md).
5. **Плановое обновление.** Список работ по разнице вложений (R11); команда `run update`; расписание запусков и команды `schedule`; сервис `indexer-daemon` с догоняющим запуском (R7); отказ `schedule on` без наблюдавшихся продления и повторного входа.
6. **Приёмка.** Живой прогон по [руководству](quickstart.md): вход, полный проход с двумя остановками, отзыв и повторный вход, включение расписания, неделя наблюдения. Протокол `acceptance.md`.

Шаги 2 и 4 независимы после шага 1. Шаг 3 зависит от шага 2, шаг 5 — от шагов 3 и 4. Полный проход (история 1) и однократный вход (история 2) дают пригодный результат без шагов 4 и 5.

## Проверка конституции

| Принцип | Решение и приёмка | Итог |
| --- | --- | --- |
| I. Состав корпуса определяется расписанием | Список прохода строится из строк расписания с материалами; выборка пилота больше не ограничивает обход — расширение корпуса принято владельцем вместе со спецификацией. Аудитория — по пометке расписания и ленте, неясное решает редактор, до решения материал закрыт. FR-01, FR-22, SC-01. | Соблюдён. Расширение корпуса требует подтверждения владельца до первого полного прохода |
| II. Права проверяются до поиска | Допуск участника — подписка на клуб (VK Donut), отдельное изменение бота от 2026-11-22; функция 003 его не меняет. Доступ оператора даёт только чтение источника и не считается допуском участника; при утрате оператором доступа к платной ленте проход останавливается, а не переносит платные публикации в открытые (FR-23). Новые материалы наследуют правила аудитории 002. Оповещения не содержат текста материалов. | Соблюдён при условии поправки к принципу II: формулировка «до проверки механизма членства — только согласованные тестировщики» устарела (задача T004) |
| III. Рекомендация подтверждается источником | Обработка материалов и карточки — из 002 без изменений. Запись без субтитров остаётся карточкой целиком со статусом ожидания источника. | Соблюдён |
| IV. Целостность опубликованного индекса | Версия по-прежнему публикуется атомарно после полной обработки; остановка прохода не оставляет частичной версии; повтор не создаёт дублей (SC-02). Отказ авторизации, лимит, пустой ответ, тайм-аут и ошибка разбора различаются (R5, R13, R14). Повторяется только затронутый материал, число попыток и проходов ограничено (R12). Пропуск публикации в ленте требует проверки и открывает оповещение; материал не снимается. Адреса файлов запрашиваются для каждой порции и не сохраняются (R10). | Соблюдён |
| V. Воспроизводимая приёмка | Пробы R6, R10 и отзыв доступа записываются с датой, средой и способом авторизации; протокол разделяет проверку на подменах, наблюдение на стенде и наблюдение оператора. Вывод о сроке автономности ограничен наблюдавшимся сроком. | Соблюдён |
| Каналы и эксплуатация | Значения доступа — только у процессов индексатора (отдельный том); ключ сообщений — только у vk-adapter (R15); коды, токены, адрес возврата и подписанные адреса исключены из журналов, БД и оповещений (FR-10, SC-04). Автоматические запуски включаются только после наблюдавшихся продления и повторного входа (R18). Возраст индекса и очередь ошибок доступны в сводке. | Соблюдён |

Повторная проверка после проектирования: нарушений нет, поправка к конституции не требуется. Серверная часть OPS-01 остаётся открытой: приёмка на ПК разработчика учитывается как проверка механизма, а не сервера. Таблица сложности не заполняется.

## Структура реализации

```text
ecoprofi/
├── indexer/
│   ├── access.py        # хранилище значений, вход, продление, состояние доступа   (новый)
│   ├── runs.py          # проход, список лекций, порции, блокировка, остановка     (новый)
│   ├── update.py        # список работ планового обновления по разнице вложений    (новый)
│   ├── alerts.py        # открытие, обновление и закрытие причин                   (новый)
│   ├── daemon.py        # цикл расписания запусков                                 (новый)
│   ├── status.py        # сводка состояния                                         (новый)
│   ├── vk_sources.py    # токен из хранилища, причина auth, ограничение частоты
│   ├── retry.py         # + SourceAuth, SourceRateLimit
│   ├── publish.py       # + номер прохода и счётчик постоянного сбоя в задании
│   ├── report.py        # + постоянные сбои, ждёт источника
│   └── __main__.py      # + access, run, schedule, requeue, status
├── bot/
│   ├── alerts.py        # очередь, отметка отправки, проверка устаревания           (новый)
│   └── api.py           # + /api/alerts/pending, /api/alerts/{id}/sent
└── vk_adapter/
    └── __main__.py      # + опрос очереди оповещений и отправка оператору
migrations/003_autonomy.sql
tests/
├── test_access.py, test_alert_rules.py, test_schedule_due.py
└── integration/         # test_migration_003.py, test_run_portions.py, test_access_lost.py,
                         # test_update_diff.py, test_permanent_failure.py, test_alerts_api.py
compose.yaml             # сервис indexer-daemon, том indexer-secrets, новые переменные
.env.example             # VK_ID_APP, ALERT_VK_USER_ID
```

Проверки 001 и 002 сохраняются; в них меняется только способ передачи токена подмене клиента VK.
