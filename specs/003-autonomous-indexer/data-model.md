# Данные автономного индексатора

Схема 002 расширяется миграцией `003_autonomy.sql`. Каталог, версии и фрагменты не меняются; повторной индексации миграция не требует.

## Сущности

| Сущность | Ключ и содержимое | Правило |
| --- | --- | --- |
| Проход (`index_run`) | Номер; вид `full` / `scheduled` / `manual`; время начала и конца; состояние `running` / `interrupted` / `done` / `paused` / `stopped` / `failed` / `skipped` / `cancelled`; причина остановки (`auth`, `rate_limit`, `ai_limit`, `paid_feed`, `schedule`, `busy`); размер порции; число записей платной ленты при последней проверке; счётчики материалов: новых, изменённых, без изменений, отложенных, сбойных; итог чтения расписания | Незавершённый проход один. `interrupted` ставится при следующем старте, если проход числится `running`, а блокировка свободна. `skipped` — плановый срок наступил при занятой блокировке или отсутствии доступа. `cancelled` — проход отменён командой `run cancel` |
| Лекция прохода (`run_lecture`) | Проход и лекция; номер порции; состояние `pending` / `done`; время завершения | Список создаётся при старте прохода в порядке расписания. Порция — очередные N лекций `pending`. Лекция получает `done`, когда каждый её материал получил итог в этом проходе |
| Задание индексации (`index_job`, расширение) | К полям 002 добавляются: номер прохода последней обработки; число проходов подряд без успеха; состояние `permanent`; причины `auth`, `rate_limit`, `ai_limit`; признак «ждёт источника» | Материал с номером текущего прохода и состоянием `done` при продолжении пропускается. Счётчик обнуляется при успехе и командой `requeue`. `permanent` автоматически не повторяется |
| Пропуск публикации (поле `lecture_post.missed`) | Число проходов подряд, в которых лента не вернула публикацию | Пропуск не снимает материал. Значение больше нуля открывает оповещение `post:<номер>`; появление публикации обнуляет счётчик |
| Состояние доступа (`operator_access`, одна строка) | Состояние `absent` / `active` / `login_required`; время входа, последнего продления и истечения рабочего токена; срок токена обновления, если источник его сообщил; время первого успешного продления; время входа после состояния `login_required`; причина последнего отказа | Значений токенов, `device_id` и кода в строке нет. Строку пишет только индексатор; bot читает её для сводки и оповещений |
| Значения доступа (файл на томе `indexer-secrets`) | Рабочий токен, токен обновления, `device_id`, номер приложения VK ID | Вне БД. Доступен только сервисам индексатора; заменяется атомарно; удаляется командой `access forget` |
| Расписание запусков (`run_schedule`, одна строка) | Утреннее и вечернее время (по Москве; вечернее может отсутствовать), признак «включено», срок последнего учтённого планового запуска | Сроков в сутки не больше двух, между ними не менее шести часов. Включение возможно только при заполненных обеих отметках проверки в состоянии доступа (R18) |
| Оповещение (`alert`) | Номер; ключ причины; вид `action` / `info`; текст; состояние `open` / `closed`; время открытия и закрытия; время и число отправок; признак «восстановление отправлено» | Одна открытая запись на ключ причины. Отправляется, если не отправлялось, либо открыто и с последней отправки прошли сутки, либо закрыто и восстановление не отправлено. Вид `info` (итог прохода) отправляется один раз и закрывается |

## Итоговое состояние материала (FR-01)

Вычисляется для отчёта, сводки и оповещений; отдельно не хранится.

| Состояние | Условие |
| --- | --- |
| Опубликован | Задание `done`, у материала есть опубликованная версия с текстом (`ready` или `partial`), действующая аудитория определена |
| Ждёт источника | Задание `done`, версия опубликована без текста: запись без пригодных субтитров. Проверяется при каждом плановом обновлении |
| Ждёт решения редактора | Версия опубликована, действующая аудитория по правилам 002 не определена или есть открытое расхождение |
| Формат не поддерживается | Причина `unsupported` |
| Постоянный сбой | Состояние `permanent` |
| Отложен (промежуточное) | Состояние `retry`: будет повторён в следующем проходе после наступления срока |

Материал, у которого задания ещё нет, в завершённом полном проходе появиться не может (SC-01).

## Переходы

**Проход.** `running` → `done` (все лекции `done`) · → `paused` (лимит VK, продолжится в следующий срок) · → `stopped` (`auth`, `ai_limit`, `paid_feed`: продолжится после устранения причины) · → `failed` (непредвиденная ошибка) · → `interrupted` (процесс остановлен). Проход в состоянии `paused`, `stopped`, `interrupted` или `failed` продолжается следующим запуском с первой лекции `pending`; новый проход не создаётся, пока прежний не завершён или не отменён оператором.

**Задание.** `queued` → `running` → `done` | `retry` | `failed`. `retry` → (три прохода подряд без успеха) → `permanent`. `permanent` → `queued` только командой `requeue`. Остановка прохода по причинам `auth`, `rate_limit`, `ai_limit` возвращает текущий материал в `queued` без изменения счётчика.

**Доступ.** `absent` → `active` (вход) → `login_required` (отказ авторизации или продления; файл значений удаляется) → `active` (повторный вход). `active` → `absent` (команда `access forget`).

**Оповещение.** `open` → `closed` (причина устранена: успешный вход, успешный проход, публикация материала, решение редактора, возвращение публикации в ленту).

## Права компонентов

| Таблица | indexer | bot |
| --- | --- | --- |
| `index_run`, `run_lecture`, `run_schedule` | чтение и запись | чтение |
| `operator_access` | чтение и запись | чтение |
| `alert` | чтение и запись | чтение, вставка (устаревание индекса), отметка отправки |
| `index_job` | как в 002 | чтение (сводка для оповещений) |

Том `indexer-secrets` подключён к `indexer` и `indexer-daemon`; сервисам `bot`, `vk-adapter` и `tests` он недоступен.
