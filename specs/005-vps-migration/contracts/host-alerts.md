# Контракт оповещений хоста

**Дата:** 2026-11-24. Расширение [контракта оповещений 003](../../003-autonomous-indexer/contracts/alerts.md) двумя причинами, которые создаёт хост VPS, а не сервисы. Схема БД и код bot / vk-adapter не меняются (research R10).

## Причины

| Ключ причины | Открывается | Закрывается | Действие оператора в тексте |
| --- | --- | --- | --- |
| `tls` | До `notAfter` сертификата `miniapp.bot-alimony.ru` осталось меньше 14 дней, либо файл сертификата не читается | Ежедневная проверка видит запас не меньше 14 дней | `sudo certbot renew` и `sudo certbot certificates`, затем проверить журнал `certbot.timer` |
| `backup` | `ecoprofi-backup.service` завершился с ненулевым кодом (дамп, проверка оглавления, sha256, загрузка или ротация) | Следующий запуск `backup.sh` прошёл полностью | `journalctl -u ecoprofi-backup -n 50`, затем повторный запуск юнита |

Для обеих причин `kind = 'action'`. Отправка, напоминание раз в сутки и одно сообщение о восстановлении выполняются по правилам 003 силами bot и vk-adapter. Получатель — `ALERT_VK_USER_ID`.

## Интерфейс `deploy/host-alert.sh`

```text
host-alert.sh open  <причина> <текст>   # создать открытую запись или обновить текст открытой
host-alert.sh close <причина>           # закрыть открытую запись, если она есть
```

- `<причина>` принимает только значения из таблицы выше (`tls`, `backup`). На другое значение скрипт отвечает кодом 2. Скрипт не пишет причины 003.
- Запись выполняется через `docker compose -f /opt/ecoprofi/compose.yaml exec -T db psql -U ecoprofi_owner -d ecoprofi -v ON_ERROR_STOP=1`. Значения передаются переменными psql (`:'cause'`, `:'body'`), а не подстановкой в текст SQL.
- `open` — одна транзакция: обновить `body` открытой записи с этим `cause_key`, а если её нет, вставить `(cause_key, kind='action', body)`. Повторный `open` не создаёт второй записи: это гарантирует `alert_open_idx`.
- `close`: `UPDATE alert SET state='closed', closed_at=now() WHERE cause_key=:'cause' AND state='open'`. Если открытой записи нет, ничего не меняется.
- Если БД недоступна, код возврата ненулевой, а сообщение уходит в журнал юнита. Оповещение в этом случае не доставляется: на это сработает `stale` или внешний мониторинг (research R11).

## Текст

Правила 003: первая строка — причина, затем время по Москве, число дней до истечения или указание на журнал юнита, и команда. Секретов, адресов бакета, путей ключей и содержимого журналов в тексте нет.

Пример: `Сертификат miniapp.bot-alimony.ru истекает через 12 дн. (2026-12-06 03:10 МСК).\nВыполнить: sudo certbot renew; sudo certbot certificates.`

## Проверка (quickstart, «Оповещения хоста»)

1. `host-alert.sh open tls "проверка"` → в течение минуты оператору приходит сообщение. `host-alert.sh close tls` → приходит одно сообщение «Восстановлено».
2. Временно задать в `/etc/ecoprofi-backup.env` неверный `RCLONE_REMOTE` → `systemctl start ecoprofi-backup.service` завершается с ошибкой → открывается `backup`. После восстановления значения и повторного запуска причина закрывается.
3. `cert-check.sh` с порогом, увеличенным через переменную `CERT_WARN_DAYS=90`, открывает `tls`, а со значением по умолчанию закрывает.
