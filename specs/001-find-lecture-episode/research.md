# Основания решений для серверного сценария

| Решение | Основание и следствие |
| --- | --- |
| Сразу поднять серверную часть через Compose | Диагностический скрипт уже находит запись и строит ссылку. Следующая неизвестная — работа всего пути от публикации до ответа участнику, включая смену прав и перезапуск. |
| Использовать две проверенные связи расписания | Посты 41120 и 30861 ограничивают объём первой загрузки. Автоматическое извлечение всех связей расписания проверяется отдельно. |
| Переиспользовать чтение VK и разбор субтитров | В текущем subtitle_passages сравниваются целые соседние строки. Проверить суффиксно-префиксное перекрытие во времени и повтор после паузы до переноса в индексатор. |
| Искать по опубликованным фрагментам в PostgreSQL | search_loop работает через input/print и ограничивает число фрагментов до группировки. Сервер фильтрует права в обоих каналах поиска, объединяет ранги и выбирает разные записи до применения лимита. |
| Применить модель эмбеддингов документа и совместимую модель запроса | Сохранять идентификатор модели и размерность вектора в описании индекса. Смена несовместимой модели требует перестроения и переключения полной версии. Порог слабого совпадения подобрать на положительном, неоднозначном и заведомо постороннем запросах. |
| Разделить вход оператора и работу бота | Оператор проходит знакомый интерактивный VK ID на ПК при загрузке. После публикации bot обслуживает участников по сохранённым данным независимо от присутствия оператора. |
| Принять переход в самом плеере | Протокол подтверждает формирование ссылки. Открытие нужной секунды проверяют из реального тестового диалога. |
