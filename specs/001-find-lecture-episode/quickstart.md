# Запуск и приёмка первого серверного сценария

Это целевой порядок проверки **после реализации**. Рабочая папка — корень проекта на Windows с Docker Compose. Для живого прогона нужны VK ID оператора с доступом к двум записям, тестовое сообщество с включёнными сообщениями и Bots Long Poll, две согласованные роли и доступ приложения к моделям AI Studio. Секрет сообщений доступен адаптеру; секреты сервисов задаются средствами конфигурации Compose.

1. Запустить стенд и выполнить предусмотренные миграции:
   
   ```powershell
   docker compose up -d --build db
   docker compose run --rm bot python -m ecoprofi.bot.migrate
   docker compose up -d bot vk-adapter
   ```

2. Через предусмотренную при реализации команду импорта настроек внести ID тестовой группы, допуски двух тестировщиков, роли и проверенную разметку аудитории двух материалов. Файл pilot-policy.json содержит группу, отображение VK ID в роли и отображение пар owner_id/video_id в аудитории. Права вступают в силу после записи в БД.
   
   ```powershell
   docker compose run --rm -v "${PWD}/pilot-policy.json:/input/policy.json:ro" bot python -m ecoprofi.bot.import_policy /input/policy.json
   ```

3. Пройти интерактивный вход VK ID на ПК. Предусмотреть диагностический режим авторизации для передачи пользовательского токена индексатору в скрытом приглашении, без аргумента командной строки и записи в журнал. Запустить одноразовый проход сервиса:
   
   ```powershell
   docker compose run --rm indexer python -m ecoprofi.indexer --control-posts 41120 30861
   ```

4. Из личного диалога клубного тестировщика отправить «загрязняющих веществ», открыть разбор 2909-р и сопоставить выдержку и стартовую позицию плеера с эпизодом 26:03–26:30. Проверить публичного участника, неизвестную роль, отзыв клубного доступа повторным импортом политики, уточнение и два одновременных диалога. Ожидать ноль закрытых результатов у участника без прав.
5. Проверить постоянство корпуса. Сохранить идентификаторы и число опубликованных версий и эпизодов. Выполнить `docker compose down`, затем `docker compose up -d db bot vk-adapter`. Сохранить том БД. Без повторного входа оператора и индексации повторить контрольный запрос, сверить запись, интервал и счётчики. Повторный импорт прежних материалов также сохраняет счётчики. Это проверка SC-05.
6. Интеграционные проверки на отдельном тестовом томе должны покрывать разрыв сети и восстановление, отзыв прав, удаление, повтор события, отсутствие дорожки, перекрытие реплик, одноимённые записи, слабый запрос и вопрос вне корпуса. Внешние сервисы заменяются фикстурами; для живого протокола используются действительные роли, источники и плеер.

Протокол содержит дату, среду, роль, версию материала, ожидаемый и фактический результаты и открытые вопросы. Для перехода в плеер записать клиент, стартовую позицию и услышанную фразу. Для диагностики исходного материала по-прежнему доступен `py -3 Test-VkUserWall.py --search-content`.
