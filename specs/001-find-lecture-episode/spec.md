# Спецификация функции «Найти эпизод лекции по вопросу»

**Идентификатор** — 001-find-lecture-episode · **Дата** — 2026-11-22 · **Статус** — выполнена, закрыта решением владельца 2026-11-22 (см. [протокол приёмки](acceptance.md), раздел 5).

Участник задаёт вопрос о материалах «ЭкобезБЕЗграниц», читает подтверждающую выдержку и одним переходом открывает нужное место записи. Так он может проверить ответ по речи лектора без ручного просмотра всей лекции.

**Граница первого релиза.** Локальный запуск означает размещение серверной части на ПК разработчика. Оператор публикует две контрольные записи один раз. Участник ищет в опубликованном корпусе через личный диалог, в том числе после перезапуска стенда без повторной загрузки источников.

## Пользовательские сценарии и проверка

### История 1. Найти и открыть эпизод (P1)

**Самостоятельная проверка.** Согласованный тестировщик с клубным доступом задаёт вопрос «загрязняющих веществ» в личном тестовом диалоге. Проверяющий открывает полученную ссылку в плеере под той же ролью.

| Шаг | Наблюдаемый результат |
| --- | --- |
| Задать контрольный вопрос | Среди первых трёх материалов есть запись разбора перечня 2909-р от 05.04.2024. По выдержке о взвешенных веществах понятно, почему запись предложена. |
| Сверить выдержку с речью | Показан интервал эпизода. Слова идут в исходном порядке. Перекрывающиеся строки субтитров не дублируют одну реплику. Реальный повтор после паузы сохранён. |
| Открыть результат | Открывается указанная запись. При воспроизведении с позиции перехода слышен нужный эпизод без ручной перемотки. Ориентир на проверенной версии записи — 26:03–26:30, начало на 1563-й секунде. |

### История 2. Получить ответ в пределах своих прав (P1)

**Самостоятельная проверка.** Один и тот же запрос выполняют тестировщики с разными правами. Для контроля выбирают запрос, по которому есть известный закрытый эпизод.

1. При подтверждённом клубном доступе участник может получить закрытый эпизод.
2. При публичных или неизвестных правах ответ содержит только публичные материалы. Закрытая карточка, выдержка, ссылка и пересказ отсутствуют, в том числе при уточнении запроса.
3. После отзыва клубных прав участник повторяет прежний запрос. Новый ответ учитывает текущие права даже при наличии ранее выданного результата. Ответы и уточнения приходят только в диалог отправителя.

### История 3. Уточнить вопрос или узнать, что эпизод не найден (P2)

**Самостоятельная проверка.** При слабом совпадении участник получает просьбу уточнить тему и может продолжить поиск в своём диалоге. Для заранее выбранного вопроса вне доступного корпуса бот сообщает об отсутствии подходящего эпизода. В ответе отсутствуют неподтверждённые цитаты и таймкоды.

### Пограничные случаи

- Если доступна только карточка записи, её можно предложить для навигации по подтверждённому описанию. Карточка без подтверждённой речи не засчитывается как найденный эпизод.
- Если у разных записей сходные названия, ссылка, интервал и выдержка каждого результата должны принадлежать одной записи. Несколько совпадений одной записи не должны вытеснять остальные материалы повторяющимися карточками.
- Если источник временно недоступен при обновлении, ранее проверенный фрагмент сохраняется в пределах действующих прав. При подтверждённом удалении материала он исключается из новых ответов.

## Требования

### Функциональные требования

| Код | Требование | Проверка |
| --- | --- | --- |
| FR-01 | Принимать вопросы согласованных тестировщиков в личном тестовом диалоге. Проверять участника и его права перед каждым поиском и уточнением. Права оператора чтения источников не предоставляют участнику доступ. | История 2, включая запрос из диалога другого участника |
| FR-02 | Искать среди связанных с расписанием записей в доступной участнику части корпуса. Выдавать до трёх разных материалов с названием, пояснением выбора и стабильной ссылкой на источник. | История 1 и случай сходных названий |
| FR-03 | Для найденного эпизода показывать читаемую выдержку и границы интервала из субтитров той же версии записи. Устранять повторы от перекрытия строк, сохраняя порядок речи и повторы после паузы. | Сверка с дорожкой и речью в истории 1 |
| FR-04 | Ссылка на эпизод должна открывать нужную запись на начале показанного интервала. Пользователю передаётся ссылка на запись, временный адрес субтитров остаётся внутренним. | Фактический переход в плеере в истории 1 |
| FR-05 | При слабом совпадении запрашивать уточнение. При отсутствии подтверждения сообщать, что подходящий эпизод не найден. Для записи без пригодных субтитров допускается только навигационная карточка. | История 3 и проверка записи без дорожки |
| FR-06 | При повторном поиске учитывать изменение прав и подтверждённое удаление. Временная ошибка повторного чтения сама по себе не снимает доступный материал с поиска и не создаёт дубликатов после восстановления. | Повтор запроса из истории 2 и проверка сбоя, восстановления и удаления |
| FR-07 | Сохранять опубликованный корпус и действующие права между запусками. После перезапуска участник может найти эпизод до следующего входа оператора и обновления источников. | SC-05: повтор контрольного поиска до и после перезапуска под обеими ролями |

### Основные сущности

- **Участник и диалог** — отправитель вопроса, его текущая аудитория и контекст уточнения.
- **Запись лекции** — материал расписания с названием, стабильной ссылкой, версией и аудиторией. У разбора может быть собственная аудитория.
- **Эпизод** — выдержка из конкретной версии записи с началом и концом интервала. Наследует права материала.

## Критерии успеха

### Измеримые результаты

- **SC-01.** Контрольный запрос возвращает разбор 2909-р в первой тройке. Редактор сверяет выдержку с дорожкой и подтверждает соответствие теме и отсутствие искусственных повторов.
- **SC-02.** За один переход из результата участник попадает к началу найденного эпизода. В протоколе записываются ожидаемая и фактическая стартовые позиции плеера и содержание услышанной реплики. Ссылка, возвращающая к началу всей записи, проверку не проходит.
- **SC-03.** В проверках публичной роли, неизвестных прав и отозванного доступа — ноль закрытых результатов и выдержек. На двух раздельных диалогах — ноль ответов, доставленных другому участнику.
- **SC-04.** Для вопроса вне корпуса и для записи без пригодной дорожки — ноль неподтверждённых эпизодов. После временного сбоя и восстановления одна запись представлена не более чем одной карточкой.

- **SC-05.** После остановки и повторного запуска стенда с сохранением данных клубный участник находит ту же запись с тем же интервалом. У публичного участника отсутствует закрытый результат. Число опубликованных версий и эпизодов не меняется; повторный вход оператора и чтение VK для восстановления корпуса не требуются.

## Допущения и границы

Основания — [конституция v1.0.0](../../.specify/memory/constitution.md) и [архитектурное решение](../../Архитектура_бота_Экопрофи.docx), приложения Б и В. Основной критерий — VTT-01. Для локального диалога применяется тестовая часть VK-02, для пригодности дорожки — VID-01, для повторного чтения — относящаяся к выдаче часть NET-01.

Для проверки используются две прямые видеозаписи из контрольных публикаций 41120 и 30861. Оператор имеет действующий доступ к источникам, роли тестировщиков известны проверяющему. На Windows уже наблюдались совпадение и формирование ссылки. Повтор живого запроса после исправления повторов, фактический переход в плеере и выдача под разными ролями входят в предстоящую приёмку. Для каждой пробы фиксируются дата, среда, роль, запись и наблюдаемый результат без секретов и временных ссылок.

Установка рабочего мини-приложения в сообществе, автоматический обход всего расписания, автономное продление авторизации индексатора на сервере клуба, поиск по документам и распознавание аудио относятся к другим этапам. Ориентир 16 успешных поисков из 20 применяется к расширенному текстовому пилоту.
