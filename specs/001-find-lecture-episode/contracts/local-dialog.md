# Контракт личного тестового диалога

**Вход.** Адаптер принимает текстовые события message_new от настроенной тестовой группы. Проверяет group_id, положительный идентификатор пользователя, личный диалог peer_id = from_id, допуск отправителя и непустой текст. Чужая группа, беседа и пользователь вне тестовой группы не запускают поиск. Допущенный пользователь без установленной роли получает только публичную часть.

**Поиск.** Входные значения — вопрос, контекст уточнения этого диалога и разрешённый снимок корпуса. Выход — один из следующих вариантов.

| Исход | Содержание |
| --- | --- |
| Найден эпизод | До трёх разных записей. Для каждой — название, основание выбора, точная выдержка, интервал и стабильная ссылка с позицией начала. Начало для ссылки округляется вниз до целой секунды, конец для отображения — вверх. |
| Только карточка | Название, основание по описанию, обычная ссылка и пометка о недоступности поиска по речи. Карточка входит в общий лимит. |
| Требуется уточнение | Один вопрос по теме доступных материалов. Ответ дополняет исходный запрос в этом диалоге. |
| Эпизод не найден | Краткое сообщение об отсутствии подтверждения в доступных материалах. |

**Доставка.** Ответ отправляется через messages.send только в исходный peer_id. При повторе одного входного события сохранять тот же random_id отправки и не продвигать контекст повторно. Сервис vk-adapter получает события через Bots Long Poll. После потери параметров подключения повторно получить их для той же группы. Секрет сообщений и токен оператора используются раздельно.

**Пример координат.** Для начала 1 563 000 мс и записи разбора 2909-р адрес имеет вид `https://vkvideo.ru/video-95098598_456240391?t=1563s`. Текст для ответа берётся из обработанной дорожки, без реконструкции цитаты. При ограниченной роли закрытая запись исключена из всех четырёх исходов, включая подсказки.

## Внутренний контракт адаптера с FastAPI

Адаптер вызывает POST /api/search по внутренней сети Compose со служебным ключом. Тело содержит event_id, group_id, peer_id, user_id и text. Сервер проверяет ключ, принадлежность группе, личный диалог и допуск тестировщика. Роль извлекается из БД при каждом обращении. В ответе 200 возвращаются event_id, peer_id, исход (found, clarify или empty), текст сообщения и массив до трёх карточек. Карточка типа episode включает material_id, title, explanation, excerpt, start_ms, end_ms и url. Тип navigation содержит только сведения по карточке и ссылку на запись.

Адаптер отправляет результат только при совпадении peer_id с исходным диалогом. Ошибка служебного ключа даёт 401, недопустимые группа или участник — 403, некорректное тело — 422. При временной недоступности сервиса повторяется тот же event_id. Сервер повторно проверяет права, сохраняет однократное применение уточнения. При неопределённом результате доставки адаптер использует прежний random_id. Пользовательский токен индексатора через этот интерфейс не передаётся.
