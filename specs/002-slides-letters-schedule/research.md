# Основания решений для поиска по слайдам и письмам

Решения приняты по коду функции 001, пробам приложения Б архитектуры и конституции. Пометка **«проба»** означает: решение выбрано, но факт, на котором оно стоит, на этом стенде не наблюдался — его проверяет первая задача реализации, а при провале действует указанный запасной путь.

## Решения

| № | Решение | Основание | Отвергнутые варианты |
| --- | --- | --- | --- |
| R1 | Расписание читается из сохранённой страницы или по адресу; оба пути дают один разбор. Команда принимает `--schedule-file` и `--schedule-url`. | В пробе найдено 279 ссылок-кандидатов, но разбор строк (дата, раздел, пометка «Клуб», «в разработке») не делался. Файл делает разбор воспроизводимым и пригодным для фикстуры. **Проба пройдена 2026-11-22**: адрес отдаёт страницу без входа (HTTP 200, 251 ссылка на публикации сообщества, обе контрольные — 41120 и 30861 — на месте). Разметка строки («Клуб», «в разработке») ещё не разобрана. Сохранённый файл остаётся запасным путём. | Разбор только по сети: проверка зависела бы от доступности VK и не повторялась бы на фикстуре. |
| R2 | Ключ строки расписания — дата и нормализованное название. Смена ссылки обновляет ту же строку; смена названия создаёт новую строку, прежняя попадает в отчёт редактору. | Ссылка появляется позже строки («в разработке»), поэтому ключом быть не может. Порядковый номер сдвигается при вставке строки. | Ключ по номеру публикации; ключ по позиции в таблице. |
| R3 | Аудитория материала выводится из двух сигналов: пометка «Клуб» в расписании и принадлежность публикации платной ленте. Любой из них даёт `club`. `public` — только если нет ни одного. Решение редактора действует, пока не изменился сигнал, который он видел. | Принцип I: пометка действует на конкретный материал, неясное решает редактор. В 001 владелец назначил посту 41120 `club`, посту 30861 `public`, а архитектура (VK-01) ждёт пометку у разбора — расхождение уже есть, и молча менять аудиторию нельзя. | Доверять только расписанию: пропущенная пометка открыла бы клубный материал. Считать непроверенную ленту открытой: запись лекции 1, закрытая в 001, после переноса стала бы публичной (замечено при первом отчёте по живой базе). Доверять только файлу политики: расписание перестало бы определять корпус. |
| R4 | Текст и изображения страниц PDF получает pypdfium2. Страница с пустым текстовым слоем распознаётся Tesseract с русской моделью внутри контейнера индексатора. | Одна библиотека даёт и текстовый слой, и растеризацию; лицензии допускают использование без раскрытия кода. Локальное распознавание не выводит текст материалов за пределы стенда. Проба на Windows (системный OCR) дала 436 символов на странице 2 — это ориентир качества. **Проба**: Tesseract на той же странице даёт текст о НВОС сопоставимого объёма. | PyMuPDF — лицензия AGPL. Облачное распознавание — конституция разрешает внешнюю обработку только для векторизации и генерации; потребовалась бы поправка и согласие владельца. Системный OCR Windows — недоступен в контейнере. |
| R5 | RTF читается библиотекой striprtf с явной обработкой кодовой страницы. Реквизиты письма (дата, номер) ищутся в начале извлечённого текста. | В пробе из контрольного письма извлечено 2417 символов с реквизитами. **Проба**: striprtf на том же письме даёт дату 08.02.2024 и номер ВЧ-09-03-34/3616 без искажений. Запасной путь — собственный разбор управляющих слов. | Конвертация через офисный пакет в контейнере — тяжёлая зависимость ради пяти писем. |
| R6 | Реквизиты считаются подтверждёнными, только если взяты из текстового слоя оригинала. Реквизиты из распознанного изображения получают состояние «не подтверждены» и участнику не показываются, пока редактор их не подтвердит. | Архитектура называет риск «ошибка OCR в номере акта». Сверку «знак в знак» автоматически гарантирует только текстовый слой. | Показывать распознанные реквизиты с оговоркой: неверный номер письма хуже его отсутствия. |
| R7 | Участник получает ссылку на публикацию с документом, название документа и номер страницы. Прямая ссылка на документ используется только после пробы. | Адрес документа из вложения содержит ключ доступа и относится к подписанным адресам, которые нельзя хранить и выдавать. Публикация стабильна и сама проверяет клубный доступ на стороне VK. **Проба**: открывается ли `doc<owner>_<id>` без ключа под клубной ролью. **Итог 2026-11-25**: открывается независимо от подписки — по прямой ссылке VK клубный доступ не проверяет. Решение владельца: остаётся ссылка на публикацию. | Выдавать адрес из вложения — нарушает правило о подписанных адресах. |
| R8 | Единица поиска — фрагмент: эпизод записи, страница презентации, часть письма. Таблица `episode` обобщается до `fragment`, поиск остаётся одним запросом по всем видам. | Объединение рангов, фильтр аудитории и перепроверка прав в 001 уже работают на одной таблице. Раздельные таблицы потребовали бы трёх копий фильтра прав — три места для ошибки доступа. | Отдельные таблицы и индексы на каждый вид. |
| R9 | Страница — один фрагмент; длинная страница делится на части с тем же номером. Письмо делится по абзацам до ~1500 знаков. Строка таблицы в RTF записывается как «заголовок графы: значение». Таблица на странице PDF не разрезается между фрагментами. | Номер страницы должен совпадать с фактическим. Целая страница сохраняет заголовки таблицы рядом со значениями. **Проба**: предел длины входа модели эмбеддингов — сверить с документацией AI Studio. | Восстановление структуры таблиц из PDF — не нужно для 5–10 лекций. |
| R10 | Страница принимается в поиск, если в ней не менее 40 букв и не менее 60 % слов — кириллические слова от трёх букв. Иначе страница помечается нечитаемой, а презентация остаётся доступной целиком. | Пограничный случай спецификации «набор обрывков». Пороги — начальные, уточняются на презентациях выборки. | Принимать всё распознанное: мусорные страницы попадают в первую тройку по случайным совпадениям. |
| R11 | Номер документа в вопросе (вида «2909-р», «ВЧ-09-03-34/3616») сравнивается точно с номерами из названия и подтверждённых реквизитов материала. Материал, найденный только по номеру, выдаётся целиком — без страницы, реквизитов и выдержки. | Открытый вопрос 001: «перечень 2909-р» давал уточнение, потому что номер есть в названии, а в речи звучит иначе. FR-06. | Нечёткое сравнение номеров: «2909-р» и «2909» — разные документы. |
| R12 | В первой тройке не более двух карточек одной лекции, если подтверждены материалы других лекций. Письмо и запись одного разбора выдаются отдельными карточками. Уточнение запрашивается, когда подтверждённых лекций больше, чем карточек в ответе, и их оценки близки; две-три лекции показываются все. | История 2 требует письмо и запись раздельно; история 3 — чтобы одна лекция не вытесняла остальные. Порог близости правится по замечаниям владельца (SC-05). | Одна карточка на лекцию: участник не увидел бы письмо рядом с записью. |
| R13 | Перечень лекций для редактора — отчёт команды индексатора в Markdown: строки, материалы, аудитория, расхождения, нечитаемые страницы. | История 3 требует «открыть перечень». Интерфейс редактора в границу релиза не входит. | Веб-страница редактора — отдельная функция. |
| R14 | Оценку проводит владелец сам в тестовом диалоге, без файла вопросов и числового порога. Исполнитель записывает его замечания в протокол и правит пороги. | Решение владельца от 2026-11-22. Корпус из четырёх строк расписания мал для статистики по 20 вопросам. | Команда автоматической оценки «16 из 20» — снята владельцем. |
| R15 | Образ делится на две цели сборки: общую (bot, vk-adapter) и индексатора с Tesseract. Тесты запускаются в образе индексатора. | Распознавание увеличивает образ на сотни мегабайт и боту не нужно. | Один общий образ, как в 001. |

## Что остаётся без изменений

Модели эмбеддингов и размерность 256, раздельные роли БД, скрытый ввод токена оператора, повторы с задержкой (`retry.py`), атомарное переключение версии (`publish.py`), однократная обработка события и доставка (`events.py`, `delivery.py`).

## Порядок проб

R1 и R9 пройдены до реализации и без участия владельца: расписание читается по адресу без входа; модель эмбеддингов принимает фрагмент в 1500 знаков (и до 12 000 знаков в пробе). R4 (распознавание) и R5 (реквизиты письма) подтверждены на синтетических документах в автоматических проверках; на реальных документах они наблюдаются при первом живом проходе `--materials`, которому нужен вход оператора. R7 проверяет владелец под клубной ролью. Каждое наблюдение записывается в протокол приёмки (принцип V). Провал R4 на реальной презентации — единственный, который возвращает решение владельцу: запасной путь требует поправки к конституции.
