# Запуск и приёмка поиска по слайдам и письмам

Целевой порядок проверки **после реализации**. Рабочая папка — корень проекта на Windows с Docker Compose. Стенд 001 настроен: `.env` заполнен, тестовое сообщество и два тестировщика есть. Форматы файлов и команд — в [контракте оператора](contracts/operator-commands.md), карточки — в [контракте ответа](contracts/search-cards.md), правила аудитории — в [модели данных](data-model.md).

Нужны: адрес расписания (читается без входа; сохранённый файл — запасной путь), VK ID оператора с доступом к выбранным публикациям. Выборка по решению владельца — первые три строки расписания с материалами и контрольная строка за 27.08.2025 (лекция № 4 и разбор 2909-р).

## 0. Автоматические проверки

```powershell
docker compose build
docker compose --profile test run --rm tests
```

Ожидается: все проверки 001 проходят (в них изменены только имена таблиц и состав полей карточки); новые проверки покрывают разбор расписания, страницу с текстовым слоем, страницу-скан, письмо с реквизитами, искажённый номер, нечитаемую страницу, документ в двух публикациях, расхождение аудитории, сбой одного вложения, перенос данных 001. Внешние сервисы заменены фикстурами.

## 1. Обновить схему

```powershell
docker compose up -d db
docker compose run --rm bot python -m ecoprofi.bot.migrate
docker compose up -d bot vk-adapter
```

Ожидается: миграция 002 применена; повторный запуск сообщает, что изменений нет. Контрольный вопрос 001 «загрязняющих веществ» под клубной ролью по-прежнему возвращает эпизод 26:03–26:30 — данные 001 перенесены без повторной индексации.

## 2. Прочитать расписание (SC-01)

```powershell
docker compose run --rm indexer python -m ecoprofi.indexer --schedule-url "https://vk.ru/@eco_manager_iso-raspisanie-lekcii-ekobezbez-granic"
docker compose run --rm -v "${PWD}/out:/out" indexer python -m ecoprofi.indexer --report /out/lectures.md
```

Ожидается в `out/lectures.md`: строка за 27.08.2025 с лекцией (публикация 41120) и разбором (публикация 30861); пометка «Клуб» у того же материала, что в расписании; строки «в разработке» присутствуют без материалов. Второй запуск первой команды сообщает ноль новых строк и связей.

## 3. Задать выборку и решения редактора

В `pilot-policy.json` вносится раздел `lectures` — ключи первых трёх строк расписания с материалами и контрольной строки за 27.08.2025 из отчёта — и при необходимости решения об аудитории. Владелец сверяет четыре ключа с отчётом.

```powershell
docker compose run --rm -v "${PWD}/pilot-policy.json:/input/policy.json:ro" bot python -m ecoprofi.bot.import_policy /input/policy.json
```

Ожидается: четыре строки в выборке и число решений. Обе контрольные записи 001 — клубные (решение владельца); открытых расхождений по ним в отчёте нет.

## 4. Обработать материалы (SC-06)

В отдельном окне: `py -3 Test-VkUserWall.py --copy-token`, затем вставить токен в скрытое приглашение.

```powershell
docker compose run --rm indexer python -m ecoprofi.indexer --materials
docker compose run --rm -v "${PWD}/out:/out" indexer python -m ecoprofi.indexer --report /out/lectures.md
```

Ожидается: для каждой презентации выборки — число страниц и число нечитаемых; для писем — состояние реквизитов. Материалы со сбоем чтения (в пробе два документа давали HTTP 504) перечислены отдельно и не мешают остальным; повтор — той же командой с `--only <ключ>`. Повторный запуск без изменений источников не создаёт новых версий. На диске стенда и в томе БД нет файлов документов.

## 5. Проверить ответы в диалоге (SC-02, SC-03, SC-04)

Из личного диалога тестового сообщества:

| Роль | Вопрос | Ожидается |
| --- | --- | --- |
| club | вопрос по содержанию презентации из выборки | Презентация в первой тройке, номер страницы; на этой странице документа есть подтверждающий текст |
| club | вопрос по письму из выборки | Письмо с датой и номером, совпадающими с оригиналом; запись той же лекции — отдельной карточкой |
| club | «перечень 2909-р» | Материал найден по номеру, без просьбы уточнить |
| public, unknown, после отзыва прав | те же вопросы | Ноль закрытых карточек, выдержек, реквизитов и ссылок |
| любая | вопрос вне корпуса | Сообщение об отсутствии материала |

Контрольная строка входит в выборку, поэтому обязательны два контрольных вопроса спецификации: «Где объясняют виды платного НВОС?» и вопрос о перечне 2909-р (письмо от 08.02.2024 № ВЧ-09-03-34/3616).

Проверяющий открывает ссылку под той же ролью и записывает в протокол клиент, открывшийся документ, фактическую страницу и сверку реквизитов с оригиналом.

## 6. Оценка владельца (SC-05)

Владелец задаёт в диалоге собственные вопросы по материалам выборки и сообщает замечания. Исполнитель записывает в протокол вопрос, роль, полученный ответ и замечание, правит пороги и повторяет проверку. Числового порога нет: шаг завершён, когда владелец подтвердил, что результат его устраивает.

## 7. Перезапуск

```powershell
docker compose down
docker compose up -d db bot vk-adapter
```

Ожидается: вопросы шага 5 дают те же материалы без входа оператора и без нового обновления; число лекций, материалов, версий и фрагментов прежнее.

Протокол приёмки ведётся в `specs/002-slides-letters-schedule/acceptance.md` и разделяет автоматическую проверку, полученный ответ и наблюдение в документе под учётной записью участника (принцип V). Секреты, токены и адреса файлов в протокол не вносятся.
