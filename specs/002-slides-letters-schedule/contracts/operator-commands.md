# Контракт команд оператора и файлов редактора

Команды запускаются через `docker compose run --rm …`. Токен оператора вводится в скрытое приглашение, как в 001; в аргументы, окружение и журнал он не попадает.

## Команды индексатора

| Команда | Действие | Результат и код выхода |
| --- | --- | --- |
| `python -m ecoprofi.indexer --schedule-file <путь>` или `--schedule-url <адрес>` | Разобрать расписание, обновить перечень лекций и связи со ссылками. Материалы не читаются, токен не нужен | Число строк: всего, с материалами, «в разработке», новых, осиротевших. 0 — успех; 2 — расписание не разобрано (перечень не меняется) |
| `python -m ecoprofi.indexer --materials` | Для лекций из выборки пилота прочитать публикации (платная и открытая ленты), обнаружить вложения и упоминания, обработать документы и записи, опубликовать версии | По каждому материалу: вид, состояние текста, страниц, нечитаемых страниц, фрагментов, состояние реквизитов. Упоминание связывается с материалом, только если он уже есть в каталоге. 0 — все обработаны; 1 — есть материалы в состоянии повтора или сбоя либо публикация не возвращена лентой (остальные опубликованы) |
| `python -m ecoprofi.indexer --materials --only <ключ материала>` | То же для одного материала — повтор после сбоя | Как выше |
| `python -m ecoprofi.indexer --report <путь.md>` | Сформировать перечень для редактора | Markdown-файл; 0 |
| `python -m ecoprofi.indexer --control-posts …` | Режим 001, сохраняется | Как в 001 |

Ключ материала — `video<владелец>_<номер>` или `doc<владелец>_<номер>`.

### Отчёт для редактора

Разделы отчёта: строки расписания с датой, разделом, состоянием и материалами; для каждого материала — вид, вид связи, публикация, аудитория по расписанию, решение редактора, действующая аудитория; отдельно — открытые расхождения аудитории, осиротевшие строки, материалы с неподтверждёнными реквизитами, нечитаемые страницы, сбои чтения. Текста материалов, ключей и адресов файлов в отчёте нет.

## Команды сервиса bot

| Команда | Действие |
| --- | --- |
| `python -m ecoprofi.bot.migrate` | Применить миграции, включая `002_documents.sql`, под ролью владельца схемы. Повторный запуск ничего не меняет |
| `python -m ecoprofi.bot.import_policy <файл>` | Импортировать файл политики версии 2 под ролью владельца схемы |

## Файл политики, версия 2

`pilot-policy.json` (в git не попадает; образец — `pilot-policy.example.json`).

```json
{
  "version": 2,
  "group_id": 100000001,
  "testers": { "100000011": "club", "100000012": "public" },
  "lectures": ["2025-08-27 негативное воздействие на окружающую среду"],
  "materials": {
    "video-100000001_456240001": "club",
    "doc100000002_600000001": "public"
  },
  "requisites": {
    "doc100000002_600000003": { "date": "2024-02-08", "number": "ВЧ-09-03-34/3616" }
  }
}
```

- `lectures` — выборка пилота: ключи строк расписания из отчёта. В этом релизе — первые три строки расписания с материалами и контрольная строка за 27.08.2025 (лекция № 4 и разбор 2909-р).
- `materials` — решения редактора об аудитории. Новая или изменённая запись фиксирует сигнал расписания, действовавший в момент импорта. Запись без изменений сохраняет прежний сигнал: открытое расхождение с расписанием повторным импортом не закрывается.
- `confirmed` — необязательный список ключей из `materials`, чья аудитория подтверждена заново при текущем расписании; закрывает расхождение без смены аудитории.
- `requisites` — реквизиты, подтверждённые редактором по оригиналу; необязательный раздел.
- Файл версии 1 (ключи вида `<владелец>_<номер>` без префикса) принимается: ключи считаются записями `video`. Ключ без префикса допустим и в файле версии 2.
- Файл без раздела `lectures` выборку не меняет.
- Повтор ключа, неизвестная аудитория, неизвестный ключ лекции — отказ без изменений в БД, как в 001.
