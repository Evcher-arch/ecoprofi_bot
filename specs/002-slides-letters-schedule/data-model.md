# Данные поиска по слайдам и письмам

Схема 001 (`migrations/001_pilot.sql`) расширяется миграцией `002_documents.sql`. Данные 001 сохраняются: записи и эпизоды переносятся на месте, без повторной индексации.

## Сущности

| Сущность | Ключ и содержимое | Правило |
| --- | --- | --- |
| Лекция (`lecture`) | Ключ строки расписания (дата + нормализованное название, без пометок аудитории). Дата, раздел, название, состояние `planned` / `has_materials` / `orphaned`, счётчик пропусков, время последнего обнаружения | Строка без ссылки хранится как `planned`. Строка, не найденная в двух обновлениях подряд, получает `orphaned` и попадает в отчёт; её материалы из поиска не снимаются без решения редактора |
| Публикация строки (`lecture_post`) | Лекция и номер публикации; роль в строке (`lecture` — тема, `review` — дополнительный материал), текст ссылки, пометка «Клуб» | Уникальна по лекции и публикации. Пометка относится к ссылке, за которой стоит. Ссылки не на публикации сообщества не сохраняются |
| Материал (`material`) | Вид `video` / `presentation` / `letter` / `document`; тип объекта VK (`video` или `doc`), владелец и номер объекта; название, формат источника, стабильная ссылка, состояние `active` / `review` / `deleted`, опубликованная версия | Уникален по типу, владельцу и номеру объекта: документ, приложенный к двум публикациям, — один материал. Материал неподдерживаемого формата ищется только по номеру документа в названии |
| Реквизиты письма (поля материала) | Дата, номер, отправитель; состояние `confirmed` / `unverified` / `absent` | `confirmed` — только из текстового слоя оригинала или по решению редактора. Участнику показываются только `confirmed` |
| Номера документов (поле материала `doc_numbers`) | Номера вида «2909-р», «ВЧ-09-03-34/3616» из названия и подтверждённых реквизитов, в нижнем регистре | Сравниваются с номерами из вопроса точно. Неподтверждённые реквизиты в поле не входят |
| Связь материала (`material_link`) | Лекция, материал, номер публикации, вид связи `attachment` / `mention`, признак платной ленты: да / нет / не проверена | Уникальна по лекции, материалу и публикации. Повторное обновление не создаёт дублей. Связи, перенесённые из 001, имеют непроверенную ленту |
| Решение об аудитории (`material_policy`) | Тип, владелец и номер объекта; аудитория `public` / `club` / `unknown`; сигнал расписания, который видел редактор; дата решения | Решение действует, пока сигнал расписания не изменился. При изменении расхождение открывается заново и не закрывается повторным импортом того же решения — только явным подтверждением |
| Решение о реквизитах (`requisite_decision`) | Тип, владелец и номер объекта; дата, номер, отправитель | Подтверждённые редактором реквизиты важнее извлечённых и сохраняются при повторной обработке файла |
| Версия материала (`material_version`) | Материал, отпечаток содержимого, версия обработчика, модель эмбеддингов; состояния карточки и текста (`ready` / `absent` / `partial`); число страниц и число нечитаемых страниц | Уникальность сочетания ключей; повтор не создаёт дублей. `partial` — часть страниц нечитаема |
| Фрагмент (`fragment`, бывший `episode`) | Версия, вид `episode` / `page` / `letter_part`; текст, полнотекстовый вектор, эмбеддинг. Для эпизода — начало и конец в миллисекундах; для страницы — номер страницы и номер части; для письма — номер части; признак распознанного текста | Эпизод: 0 ≤ начало < конец, страница не задана. Страница: номер ≥ 1, номер части ≥ 1, время не задано. Часть письма: номер части ≥ 1. Аудитория наследуется от материала |
| Задание индексации (`index_job`) | Тип, владелец и номер объекта; состояние, попытка, причина сбоя (`timeout`, `empty`, `denied`, `parse`, `deleted`, `unsupported`), время повтора | Повторяется только затронутый материал; не более трёх попыток |
| Выборка пилота (`pilot_lecture`) | Ключ строки расписания | Документы обрабатываются только для лекций из выборки (первые три строки расписания с материалами и контрольная строка за 27.08.2025 (лекция № 4 и разбор 2909-р)). Каталог строк ведётся для всего расписания |

Допуск участника, контекст диалога, событие и журнал операций не меняются.

## Действующая аудитория материала

Определяется при каждом поиске, а не сохраняется во фрагменте.

1. **Сигнал расписания.** Берутся связи материала, чья публикация названа в расписании. `club` — если хотя бы одна такая публикация помечена «Клуб» или принадлежит платной ленте. `public` — если ни одна не закрыта и лента каждой проверена. Сигнала нет — если материал не связан с расписанием или лента хотя бы одной публикации ещё не проверена.
2. Решения нет — действует сигнал. Нет ни решения, ни сигнала — материал закрыт (правило 001).
3. Есть решение, сигнала нет либо он тот же, что видел редактор, — действует решение.
4. Есть решение, но сигнал изменился либо решение принято до появления сигнала (все строки 001) и не совпадает с ним — действует более строгая из двух аудиторий, расхождение попадает в отчёт.
5. Решение `unknown` или материал в состоянии `review` — материал не выдаётся никому.

Строгость: `unknown` > `club` > `public`.

## Состояния и переходы

**Лекция.** `planned` → `has_materials` при появлении первой ссылки на публикацию. Любое состояние → `orphaned`, если строка не найдена в двух обновлениях подряд; обратно — при повторном появлении.

**Материал.** Новый → `active` при опубликованной версии. `review` ставит редактор, и повторная обработка его не снимает. → `deleted` при подтверждённом удалении публикации, если у материала не осталось других связей. Один пропуск в ленте удалением не считается (как в 001).

**Версия.** Индексатор готовит фрагменты новой версии целиком, затем одной транзакцией переключает указатель опубликованной версии, обновляет реквизиты и номера документов и завершает задание. Сбой до переключения оставляет прежнюю версию. Оригинал файла после обработки не сохраняется.

## Перенос данных 001

- `episode` переименовывается в `fragment` с видом `episode`; интервалы сохраняются.
- `material.video_id` становится номером объекта с типом `video`; `material.lecture_id`, `post_id` и `link_type` переносятся в `material_link` с непроверенной лентой.
- Номера документов записей заполняются из названий.
- Условная строка `pilot-control` заменяется настоящей строкой расписания при первом обновлении: связи материалов 001 перепривязываются по номеру публикации, пустая условная строка удаляется.
- Строки `material_policy` получают тип `video` и пустой «увиденный сигнал» — к ним применяется правило 4.

Права ролей БД: bot читает каталог целиком; indexer пишет в `lecture`, `lecture_post`, `material`, `material_link`, `material_version`, `fragment`, `index_job` и только читает `material_policy`, `pilot_lecture`, `requisite_decision` — их меняет импорт решений редактора под ролью владельца схемы.
