# Данные поиска по слайдам и письмам

Схема 001 (`migrations/001_pilot.sql`) расширяется миграцией `002_documents.sql`. Данные 001 сохраняются: записи и эпизоды переносятся на месте, без повторной индексации.

## Сущности

| Сущность | Ключ и содержимое | Правило |
| --- | --- | --- |
| Лекция (`lecture`) | Ключ строки расписания (дата + нормализованное название). Дата, раздел, название, состояние `planned` / `has_materials` / `orphaned`, время последнего обнаружения в расписании | Строка «в разработке» и строка без ссылки хранятся как `planned`. Строка, исчезнувшая из расписания, получает `orphaned` и попадает в отчёт; её материалы из поиска не снимаются без решения редактора |
| Материал (`material`) | Вид `video` / `presentation` / `letter` / `document`; тип объекта VK (`video` или `doc`), владелец и номер объекта; название, формат источника, состояние `active` / `review` / `deleted`, опубликованная версия | Уникален по типу, владельцу и номеру объекта: документ, приложенный к двум публикациям, — один материал. Материал `document` (неподдерживаемый формат) ищется только по названию |
| Реквизиты письма (поля материала) | Дата, номер, отправитель; состояние `confirmed` / `unverified` / `absent` | `confirmed` — только из текстового слоя оригинала или по решению редактора. Участнику показываются только `confirmed` |
| Связь материала (`material_link`) | Лекция, материал, номер публикации, вид связи `attachment` / `mention`, роль в строке (`lecture` / `review`), аудитория по расписанию, признак платной ленты | Уникальна по лекции, материалу и публикации. Повторное обновление не создаёт дублей. Ссылка для участника строится от публикации этой связи |
| Решение об аудитории (`material_policy`) | Тип, владелец и номер объекта; аудитория `public` / `club` / `unknown`; сигнал расписания, который видел редактор; дата решения | Решение действует, пока сигнал расписания не изменился. При изменении расхождение открывается заново |
| Версия материала (`material_version`) | Материал, отпечаток содержимого, версия обработчика, модель эмбеддингов; состояния карточки и текста (`ready` / `absent` / `partial`); число страниц и число нечитаемых страниц | Уникальность сочетания ключей; повтор не создаёт дублей. `partial` — часть страниц нечитаема |
| Фрагмент (`fragment`, бывший `episode`) | Версия, вид `episode` / `page` / `letter_part`; текст, полнотекстовый вектор, эмбеддинг. Для эпизода — начало и конец в миллисекундах; для страницы — номер страницы и номер части; для письма — номер части; признак распознанного текста | Эпизод: 0 ≤ начало < конец, страница не задана. Страница: номер ≥ 1, время не задано. Аудитория наследуется от материала |
| Поисковая подпись материала (поле материала) | Название и подтверждённые реквизиты в виде, пригодном для точного поиска номеров | Обновляется вместе с публикацией версии. Неподтверждённые реквизиты в подпись не входят |
| Задание индексации (`index_job`) | Тип, владелец и номер объекта; состояние, попытка, причина сбоя (`timeout`, `empty`, `denied`, `parse`, `deleted`, `unsupported`), время повтора | Повторяется только затронутый материал; не более трёх попыток |
| Выборка пилота (`pilot_lecture`) | Ключ строки расписания | Документы обрабатываются только для лекций из выборки. Каталог строк ведётся для всего расписания |

Допуск участника, контекст диалога, событие и журнал операций не меняются.

## Действующая аудитория материала

Определяется при каждом поиске, а не сохраняется во фрагменте.

1. Сигнал расписания: `club`, если хотя бы одна связь материала помечена «Клуб» или принадлежит платной ленте; иначе `public`.
2. Есть решение редактора, и сигнал, который он видел, совпадает с текущим — действует решение.
3. Есть решение, но сигнал изменился либо решение принято до появления сигнала (все строки 001) и не совпадает с ним — действует более строгая из двух аудиторий, расхождение попадает в отчёт.
4. Решение `unknown` или материал в состоянии `review` — материал не выдаётся никому.

Строгость: `unknown` > `club` > `public`.

## Состояния и переходы

**Лекция.** `planned` → `has_materials` при появлении первой связи. Любое состояние → `orphaned`, если строка не найдена в двух обновлениях подряд; обратно — при повторном появлении.

**Материал.** Новый → `active` при опубликованной версии и определённой аудитории; → `review` при открытом расхождении, которое нельзя разрешить строгим правилом (решение `unknown`); → `deleted` при подтверждённом удалении публикации или документа. Один пропуск в ленте удалением не считается (как в 001).

**Версия.** Индексатор готовит фрагменты новой версии целиком, затем одной транзакцией переключает указатель опубликованной версии, обновляет поисковую подпись и завершает задание. Сбой до переключения оставляет прежнюю версию. Оригинал файла после обработки не сохраняется.

## Перенос данных 001

- `episode` переименовывается в `fragment` с видом `episode`; интервалы сохраняются.
- `material.video_id` становится номером объекта с типом `video`; `material.post_id` и `link_type` переносятся в `material_link`.
- Условная строка `pilot-control` заменяется настоящей строкой расписания при первом обновлении: связи материалов 001 перепривязываются по номеру публикации, пустая условная строка удаляется.
- Строки `material_policy` получают тип `video` и пустой «увиденный сигнал» — к ним применяется правило 3.

Права ролей БД: bot читает `lecture`, `material`, `material_link`, `material_policy`, `material_version`, `fragment`; indexer пишет в них, кроме `material_policy` (её меняет только импорт решений редактора под ролью владельца схемы).
