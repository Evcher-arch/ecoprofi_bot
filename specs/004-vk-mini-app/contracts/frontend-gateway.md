# Интерфейс и публичный шлюз 004

**Дата:** 2026-11-23. Планируемое поведение; реализация не выполнена. Связанные документы: [API](miniapp-api.md), [план](../plan.md).

## Один экран чата

| Состояние | Что видит участник | Действие |
| --- | --- | --- |
| Инициализация | Название «Найти лекцию», индикатор входа. | Дождаться Bridge и серверного входа. |
| Неподтверждённый запуск | Предложение открыть приложение из сообщества «Экопрофи». | Открыть штатный вход; нет ручного VK ID/токена. |
| Нет подписки | Объяснение доступа и кнопка клуба. | Перейти по CLUB_URL или повторить проверку после оформления. |
| Проверка недоступна | Понятная временная ошибка. | Повторить; материалы не отображаются. |
| Готов | Заголовок, «Новый диалог», история, поле вопроса, счётчик и «Отправить». | Вопрос, длина до 2000 code points. |
| В очереди / поиск | Один вопрос и состояние обработки. | Дождаться; повторный клик не создаёт запись. |

| Найдено | Ответ и до трёх карточек. | Открыть материал по стабильной ссылке. |
| Нет результата | Обоснованный ответ существующего поиска. | Новый вопрос либо новый диалог. |
| Ошибка попытки | Ошибка без технических данных. | Повторить тот же ID, если retry_allowed; иначе новый вопрос. |
| Источник изменён | Предложение нового поиска, без прежнего ответа. | Новый вопрос с новым ID. |
| Сессия истекла | Предложение заново открыть приложение. | Новый подтверждённый вход; нет переноса старой истории. |

## Рекомендации по поиску

FR-15, решение владельца 2026-11-25. Тексты фиксированы во frontend; модель их не генерирует. Ответы чат-бота VK и общий `ecoprofi/bot/cards.py` не меняются: дополнения к уточнению и пустому результату добавляет Mini App по полю `outcome`.

Рекомендации отражают фактическое устройство поиска: фрагмент подтверждается, когда в нём найдено не меньше 60% слов запроса (с учётом окончаний); номер документа подтверждает материал по точному совпадению; векторная близость участвует только в ранжировании.

| Место | Текст |
| --- | --- |
| Placeholder поля вопроса | Например: «4-ОС сборы», «инвентаризация выбросов», «2909-р» |
| Раскрываемый блок «Как искать» под полем (по умолчанию свёрнут) | см. ниже |
| Дополнение к `clarify` (под текстом ответа) | Можно ответить коротко — например, «для воздуха» или «форма 2-ТП»: уточнение добавится к прошлому вопросу. Если тема новая, просто задайте новый вопрос. |
| Дополнение к `empty` (под текстом ответа) | Попробуйте другие слова: сокращение вместо полного названия, номер документа или название формы. |
| Подпись к «Новый диалог» | Начните заново, если меняете тему. |

Блок «Как искать»:

1. **Пишите 2–4 ключевых слова, а не целую фразу.** «плата за сбросы» сработает лучше, чем «подскажите, как правильно считать плату, если у нас есть сбросы»: чем длиннее вопрос, тем больше его слов должно встретиться в одном фрагменте лекции.
2. **Используйте слова, которые звучат в лекциях.** Поиск находит сказанное дословно, с учётом окончаний («выброс», «выбросы», «выбросов» — одно слово). Синонимы и пересказ он узнаёт хуже.
3. **Пробуйте и сокращение, и полное название.** Не нашлось «водные биоресурсы» — попробуйте «ВБР», и наоборот. То же для «НВОС» / «негативное воздействие», «ПЭК» / «производственный экологический контроль».
4. **Номер документа или формы — как в оригинале:** «2909-р», «4-ОС», «2-ТП (воздух)», «приказ 369». По номеру материал находится даже без совпадения в тексте.
5. **Одна тема — один вопрос.** «выбросы и отходы и сбросы» лучше разбить на три отдельных вопроса.

Блок доступен с телефона без горизонтальной прокрутки, раскрывается кнопкой с `aria-expanded`; состояние раскрытия не хранится между запусками.

## Карточки и оформление

Резервное пояснение при допустимом сбое генератора показывается как существующая карточка; новый интерфейс не дописывает ответ моделью. Текст сообщения и карточки оформляются без дублирования одинаковых выдержек на экране: сводный текст для found не повторяет все поля карточек второй раз.

Видеокарточка показывает интервал, презентация — страницу и пометку OCR при наличии, письмо — только подтверждённые реквизиты. Navigation/material — источник целиком, без добавленных цитат, страниц или таймкодов. Типы и null-поля берутся из API; координаты не вычисляются по предположениям клиента.

Интерфейс адаптивен к телефону и компьютеру, светлой/тёмной теме и экранной клавиатуре. Поле ввода и кнопка доступны без горизонтальной прокрутки; ожидание и ошибка читаются вспомогательными средствами. Enter отправляет на компьютере, Shift+Enter вставляет строку; IME composition не отправляет вопрос. Отдельная видимая кнопка работает на телефоне. Счётчик использует Unicode code points (`Array.from`), а не число UTF-16 code units.

## Вход и состояние вкладки

При первом запуске захватить исходную query, выполнить `VKWebAppInit`, затем серверный POST /session. При наличии токена этой вкладки сначала POST /session/resume с исходной query. После успеха загружать историю. Ошибки Bridge не заменяются подставным user ID. Текущая поддержка API Bridge, параметры запуска, перезагрузка и открытие ссылок сверена с официальной документацией; страница пробы и контрольные ссылки открыты владельцем. По его решению от 2026-11-23 реализация продолжается на test-db/UI, а повторная проверка реальной подписи, перезагрузки, iframe и установка в сообщество перенесены на целевой сервер. До этих наблюдений живой контракт не считается полностью подтверждённым; серверная HMAC-проверка и отказ при её отсутствии обязательны.

sessionStorage содержит только bearer, expires_at, dialog_id и ID незавершённого обращения. Launch query не копируется в persistent storage, историю браузера вручную, сообщения или диагностические события. Параметры остаются в адресе запуска, чтобы перезагрузка могла подтвердить исходный запуск; на сервере и gateway query не журналируется. `Referrer-Policy: no-referrer` предотвращает передачу адреса источникам и ресурсам.

Тексты, ответы и карточки — только в памяти страницы. При возвращении из скрытого состояния диалог остаётся на экране, история и допуск перепроверяются в фоне; ответ 401/403/503 немедленно скрывает выдачу, `invalidated` заменяет ответ. Если вкладка была скрыта дольше 10 минут, прежняя выдача не показывается до проверки API (решение владельца 2026-11-25: исчезновение диалога при переключении окон неудобно). Смена аккаунта/launch digest приводит к очистке локального состояния и новому входу. Два независимых запуска создают две сессии. Копия той же вкладки с тем же bearer считается тем же диалогом, а не независимым запуском; это проверяется отдельно.

ID обращения создаётся до отправки и сохраняется до однозначного исхода. Сетевой повтор использует прежние ID и текст из памяти. После перезагрузки сначала GET по сохранённому ID: найденное состояние восстанавливает вопрос с сервера. Если регистрация не подтверждена, не создавать новый запрос автоматически; сообщить, что отправка не подтверждена, и дать повторно ввести вопрос с сохранённым ID. Сервер отклонит изменённый текст, если исходный запрос всё же был зарегистрирован.

После «Нового диалога» любая поздняя реакция прежнего POST/GET игнорируется по dialog_id. Повтор нажатия «Новый диалог» во время его запроса использует тот же созданный ID. Закрытый старый диалог не может стать текущим из-за запоздавшего ответа.

## Источники и отдельный канал администрации

Ссылки открываются по клику, только `https:` и только ожидаемые домены существующих источников (`vk.com`, `vk.ru`, `vkvideo.ru` и подтверждённые при реализации адреса документов). Не разрешать `javascript:`, произвольный HTML и ссылки от модели. `target=_blank` использует `rel=noopener noreferrer`; если клиент VK не открыл новое окно, остаётся доступна обычная ссылка. Переход к странице/таймкоду проверяется в источнике; его поддержка не обещается заранее.

Mini App не запрашивает право отправки сообщений и не вызывает `messages.send`. Кнопка «Написать сообщение» сообщества остаётся самостоятельным каналом. Служебное существующее оповещение о сбое подписки допускается; оно не содержит текст поискового диалога.

## Шлюз и настройки

| Параметр | Расположение | Значение / смысл |
| --- | --- | --- |
| MINIAPP_ENABLED | bot | По умолчанию false; включить router/worker только при полных настройках. |
| MINIAPP_APP_ID | bot | Зарегистрированное Mini App, положительный ID. |
| MINIAPP_APP_SECRET | Только bot | Защищённый ключ проверки подписи; не VITE-переменная. |
| MINIAPP_PUBLIC_ORIGIN | bot и gateway | Точный HTTPS-origin текущего туннеля; меняется при смене адреса. |
| CLUB_URL | bot | Проверенная стабильная HTTPS-ссылка на клуб; обязательна для live-проверки отказа. |
| CLUB_GROUP_TOKEN / CLUB_EXEMPT_IDS / CLUB_CACHE_SECONDS | Только bot, существующие | Общие настройки подписки; не дублировать. |

Сроки и лимиты плана реализовать общими серверными константами с подменой часов в тестах. UI получает допустимую длину и expires_at от API. Секреты не вшиваются в JS; публичный app ID секретом не является.

Gateway публикует только `127.0.0.1:8080` на ПК. Публичный HTTPS-вход — постоянный Cloudflare Tunnel (R15); сервис `miniapp-tunnel` в Compose использует network namespace шлюза и маршрут `http://127.0.0.1:8080`. TLS клиента заканчивается в Cloudflare, соединение до коннектора зашифровано. Origin CA, публичный 443 и NAT не нужны. Gateway раздаёт production build; `/api/miniapp/v1/` проксируется в `bot:8000`, разрешённые методы ограничены контрактом, прочие — 405. Неизвестные и служебные API (`/api/search`, `/api/delivered`, `/api/alerts/*`) закрыты даже с X-Service-Key. PostgreSQL и management endpoints наружу не публикуются.

Адрес участника восстанавливается из `CF-Connecting-IP` только от loopback, по которому обращается коннектор (`deploy/miniapp-realip.inc`). Остальные источники не доверены; `X-Forwarded-For` и `X-Real-IP` к bot выставляет шлюз. Токен туннеля передаётся только miniapp-tunnel через файл Compose secret, исключённый из Git и Docker build context.

Авторизация bearer и same-origin fetch не требуют cookies. Сервер проверяет Origin у изменяющих запросов по MINIAPP_PUBLIC_ORIGIN; CORS для других origin закрыт. Origin и CORS не заменяют авторизацию. Host/forwarded headers доверяются только настроенному шлюзу, а не произвольному входному заголовку.

Заголовки: API `Cache-Control: no-store`; HTML `no-store`; хешированные assets могут кэшироваться; `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`. CSP: scripts/connect/resources по минимальному списку собранного приложения; без inline-исполнения пользовательского текста, без сторонних аналитик. Начальный frame-ancestors: `https://vk.com https://*.vk.com https://vk.ru https://*.vk.ru`; проверить эти родители в живом запуске и при необходимости уточнить явно, без wildcard для всего интернета. Не устанавливать X-Frame-Options DENY/SAMEORIGIN, ломающий встраивание. Доверие iframe не заменяет проверку подписи.

Gateway ограничивает тело 32 KiB и запросы одного IP (10/сек., burst 20); сервер дополнительно ограничивает очередь и объём сессии. Ответы 429 не содержат материалов. Отключить access log с request URI/query и debug-логирование body/headers у gateway, uvicorn, httpx и туннеля. Эксплуатационные события пишутся через allowlist telemetry. Отдельный smoke с искусственным секретом проверяет все доступные локальные логи и сборку.

**Проверено 2026-11-23 (T056, автоматически, без живого VK):** `deploy/miniapp-nginx.conf` + `deploy/miniapp-proxy.inc` — access_log off, server_tokens off, 32 KiB, 10 r/s burst 20 → JSON 429, `X-Service-Key` очищается при проксировании, неизвестные `/api/*` → JSON 404 без HTML, X-Frame-Options не выставляется, CSP с frame-ancestors vk.com/vk.ru. Middleware bot проверяет Origin только на `/api/miniapp/v1/*`: чужой Origin → 403; отсутствие Origin допускается (мобильный WebView), авторизация — подпись и bearer. Ошибки валидации не отражают тело (`invalid_input`). Uvicorn запускается с `--no-access-log`. Список родителей frame-ancestors подлежит подтверждению живым запуском на целевом сервере.

При недоступном backend уже открытая страница показывает сетевую ошибку. Если не загружается сам HTTPS-адрес, допустима ошибка VK/браузера; локальный интерфейс не может отобразить её до загрузки. Offline/service-worker кэш истории в 004 не добавляется.
