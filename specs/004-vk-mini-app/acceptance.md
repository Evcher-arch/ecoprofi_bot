## Проверка возврата к Cloudflare Tunnel, 2026-11-24 (R15)

- Compose с профилями miniapp/tunnel проходит `config --quiet`; образ шлюза собран, `nginx -t` успешен. Образ `cloudflare/cloudflared:2026.11.1` загружен.
- `test_miniapp_gateway.py`: **6 passed** в изолированном контейнере без рабочей БД. Первый запуск на стандартном bridge дал 2 тайм-аута из-за отсутствия DNS Docker; после подключения отдельной сети и DNS alias bot все проверки прошли. Инструкция запуска теста исправлена.
- Отдельная временная диагностическая локация в тестовом контейнере: запрос с loopback восстанавливает адрес `203.0.113.42` из CF-Connecting-IP; запрос из соседнего контейнера с тем же заголовком сохраняет реальный адрес соседа. Диагностическая локация не входит в рабочий образ.
- Рабочий miniapp-gateway пересоздан: публикует только `127.0.0.1:8080`, локальный HEAD `/` → **200**, присутствуют CSP для VK, no-store, nosniff и no-referrer.
- Постоянного туннеля и токена пока нет (подтверждено владельцем). Коннектор не запущен, DNS/маршрут аккаунта и внешний HTTPS не проверены. Это не закрывает T028/T058 и живую приёмку VK.

### Попытка подключения после получения токена, 2026-11-24

Файл токена присутствует и игнорируется Git; содержимое не выводилось. `miniapp-tunnel` запущен. QUIC/UDP: тайм-ауты; после явного `--protocol http2`: `TLS handshake with edge error: EOF`. Локальная готовность `127.0.0.1:20241/ready` → 503. TLS-проверки двух edge-адресов с Windows напрямую и через существующий SOCKS-прокси дали аналогичный EOF, включая запуск вне sandbox; настройки прокси не менялись. Причина сетевого обрыва точно не установлена, валидность токена сервером не подтверждена.

Внешний HEAD `https://miniapp.bot-alimony.ru/` → 522 от Cloudflare; локальный HEAD шлюза → 200. Маршрут аккаунта ещё не подтверждён пользователем. Коннектор оставлен с автоповтором и HTTP/2, порт диагностики доступен только внутри общего namespace. Публичная приёмка остаётся открытой.
